# LogWatcher 배포 — 전사 8색 (Longyin Q2000)

> 이 패키지는 **전사 8색 전용**입니다. 다른 장비(Flexi·Topaz·Epson)는 각자 패키지를 쓰세요.
> 빌드 2026-08-05 · self-contained(.NET 내장, 별도 설치 불필요) · win-x64

---

## 0. 이 장비가 특별한 이유 (읽고 시작하세요)

전사 8색은 **한 PC 안에 프로그램이 2개** 돌아갑니다.

| 프로그램 | 하는 일 | 아는 것 | **모르는 것** |
|---|---|---|---|
| neoStampa | 리핑 · 합판 배치 | 도안 이름, 합판에 뭐가 들어갔나 | **출력이 됐는지** (취소를 기록하지 않음) |
| PrintExp_X64 | 실제 출력 | 완료 · 취소 · 진짜 걸린 시간 | **도안이 뭔지** (파일명을 못 받음) |

→ 그래서 이 패키지는 **두 로그를 읽어 합친 다음 1건**으로 보냅니다.
따로 보내면 출력 1건이 실적에 **2번** 잡힙니다.

두 로그는 폴더 이름의 시각으로 이어집니다 (실측 133건 전부 오차 2초 이내).

---

## 1. 설치 (약 15분)

### ① 폴더 복사

이 폴더 전체를 대상 PC의 **`C:\Logwatcher\`** 에 복사합니다.
(Z: 에서 바로 실행하지 말고 반드시 로컬로 복사)

### ② `appsettings.json` 확인

서버 주소와 키가 이미 들어 있습니다. 그대로 두면 됩니다.

```json
{ "MesApiUrl": "https://webapp-9i0.pages.dev", "ApiKey": "..." }
```

### ③ `equipment.json` — 호기별로 파일이 다릅니다

**두 대의 PrintExp 설치 폴더 이름과 로그 위치가 서로 다릅니다.** 호기 번호만 바꾸면 안 됩니다.

| PC | 쓸 파일 | `print_log_dir` |
|---|---|---|
| `DESKTOP-5C9D04J` (1호기) | `equipment.json` 그대로 | `C:\PrintExp_X64\Log\main` |
| `PC-202605141926` (2호기) | `equipment.TRANS-8C-02.json` → **`equipment.json` 으로 이름 변경** | `C:\PrintExp_X64_V5.7.6.5.103.BS_20220530\Log` |

2호기는 로그가 `Log\` **바로 아래** 있습니다 — `main` 하위폴더가 없습니다.

> ⚠️ 서버에 등록된 id 와 **글자 하나까지** 같아야 합니다. 다르면 이벤트는 쌓이는데
> 장비 온라인 표시만 조용히 안 됩니다.

### ④ 두 경로가 실제로 있는지 확인 — **추정값이므로 반드시**

PrintExp 폴더 이름은 PC마다 다릅니다. 먼저 실제 이름을 찾습니다:

```
dir C:\ /b | findstr /i PrintExp
```

나온 이름으로 두 경로를 확인합니다:

```
dir "C:\Users\Public\Documents\neoStampa 10\Log"    ← 날짜 폴더들이 보여야 함
dir "C:\<나온이름>\Log"                              ← Log[2026_08_09].txt 가 여기 있으면 이 경로
dir "C:\<나온이름>\Log\main"                         ← 여기 있으면 이 경로
```

`Log[날짜].txt` 가 **실제로 있는 쪽**을 `equipment.json` 의 `print_log_dir` 에 적습니다.
**역슬래시는 두 개(`\\`)** 로 씁니다.

### ⑤ 파싱 확인 — 서버로 아무것도 안 보냅니다

```
C:\Logwatcher\LogWatcher.exe --test TRANS-8C-01
```

**정상이면 이렇게 나옵니다:**

```
[TRANS-8C-01] OK 55분  장례용태극기-출력(290-150).eps
[TRANS-8C-01] CANCEL 21분  장례용태극기-출력(290-150).eps
  [OK] 장례용태극기-출력(290-150).eps
    Size: 1500 X 14524.1
```

| 보이는 줄 | 뜻 |
|---|---|
| `OK 55분 도안명` | 정상. 실제 출력에 55분 걸렸다는 뜻 |
| `CANCEL 21분 도안명` | 출력 중 취소됨 — **정상 기록**입니다 |
| `[NEST] 선언 3 / 복원 3 → OK` | 합판. 도안 3종이 한 판에 있었음 |
| `결과 미확정 블록 건너뜀` | **정상**. 완료/취소 기록이 없는 잡 |
| `⚠ 리핑 잡을 못 찾음` | ⚠️ 많이 나오면 `rip_log_root` 경로가 틀렸습니다 |
| `Events found: 0` | ⚠️ 아래 §3 참조 |

### ⑥ 서비스 등록 (관리자 권한)

`install-service.bat` → **마우스 오른쪽 → 관리자 권한으로 실행**

### ⑦ 웹에서 확인

- `https://webapp-9i0.pages.dev/equipment` → 해당 장비 **온라인**
- `https://webapp-9i0.pages.dev/production` → 출력 1건 후 이벤트가 뜨는지

> `/rip` 페이지는 폐기됐습니다. 접속하면 빈 화면이니 `/equipment` 를 보세요.

## 1-B. 이미 설치된 PC 갱신 (2026-08-09 이후 필수)

프로그램만 바꾸면 됩니다. **`equipment.json` 과 `appsettings.json` 은 덮어쓰지 마세요** —
그 PC에 맞춰 고쳐둔 경로·호기번호가 날아갑니다.

관리자 권한 명령 프롬프트에서:

```
nssm stop LogWatcher
robocopy "Z:\Designs\LogWatcher-transfer-8c" "C:\Logwatcher" /E /XF equipment.json appsettings.json
nssm start LogWatcher
sc query LogWatcher
```

`STATE : 4  RUNNING` 이면 끝입니다. 쌓인 데이터·설정은 그대로입니다.

> **왜 갱신해야 하나** — 2026-08-09 이전 빌드는 **자정을 넘길 때 전날 로그를 처음부터 다시 읽습니다.**
> 설치한 날 밤에도 일어나서, **설치 전에 출력한 그날 오전 작업까지 뒤늦게 올라옵니다.**
> "처음 켠 시점부터 기록" 이라는 동작과 어긋나므로 그 전에 갱신하는 게 좋습니다.

## 2. 처음 켠 뒤 알아둘 것

- **과거 출력은 올라오지 않습니다.** 서비스를 켠 시점부터 기록합니다. (정상 동작)
- 카드가 자동으로 붙으려면 **도안 파일명이 주문과 연결**돼 있어야 합니다.
  전사는 파일명에 주문번호가 없어서 처음엔 안 붙습니다 →
  `/production` → **「출력파일 연결」 탭**에서 한 번 연결하면 그 뒤로는 자동입니다.

## 3. 문제가 생기면

| 증상 | 원인 | 조치 |
|---|---|---|
| `Events found: 0` | 서비스를 켠 뒤 출력이 아직 없음 | 정상. 출력 1건 내고 다시 `--test` |
| 〃 | `print_log_dir` 경로 오타 | 탐색기로 실제 경로 확인 |
| `⚠ 리핑 잡을 못 찾음` 다수 | `rip_log_root` 경로 오타 | 〃 |
| 서비스만 실패, 콘솔은 정상 | 설치 스크립트 경로 문제 | 이벤트 뷰어에서 **nssm EventID 1010** 확인 |
| 웹에 장비가 오프라인 | 서버에 `equipment_id` 미등록 | 관리자에게 id 확인 요청 |
| 한글이 깨져 보임 | 콘솔 코드페이지 | 파싱은 정상. 판단에만 영향 |

### 되돌리기

서비스를 멈추면 즉시 중단됩니다. 데이터가 지워지지는 않습니다.

```
nssm stop LogWatcher
nssm remove LogWatcher confirm
```

## 4. 다른 장비에 붙일 때 — `--probe`

로그가 **어디 있는지 모르는 장비**(수성·평판·간판 등)를 세팅할 때 씁니다.

```
LogWatcher.exe --probe
```

1. `MESPROBE-...` 이름을 만들어 줍니다.
2. **아무 작은 파일이나 그 이름으로 저장해 평소대로 출력**합니다. (작게 — 원단·잉크가 실제로 듭니다)
3. Enter → 바뀐 파일들 안에서만 그 이름을 찾아 **로그를 확정**하고 `equipment.json` 초안을 뽑아 줍니다.

인코딩·로그 형태·프로그램이 몇 개인지까지 같이 알려줍니다.
**마커 출력은 서버가 무시하므로 실적에 잡히지 않습니다** — 몇 번을 돌려도 안전합니다.

> 전사 8색은 이미 다 파악돼 있어 `--probe` 를 돌릴 필요가 없습니다.
