## 지금 사용자가 하는 일

**직접 테스트 중.** 원단 발주 → 입고 → 검수를 손으로 돌려 본다.
담당 = 동산기획 용준님 · 선명 강지영 과장. 범위 = **원단만, 2주**.
성공 기준 = 그 2주 **원단 매입에 껍데기 라인 0건**.

## 결정과 이유 (다시 논하지 말 것)

- **발주=의도(롤 수·예상) / 입고=사실(실측).** 정밀도를 같게 요구하면 아무도 안 쓴다 —
  실제로 그래서 발주가 2026-08-06 에 멈췄고 입고 검수 전표가 **0건**이었다.
- **「발주 없으면 입고 불가」는 일부러 안 넣었다.** 막으면 시스템 밖으로 나간다.
  허용하고 `adhoc_source='RECEIVING'` 표시를 남긴다. **규정은 한 달 치 숫자를 보고 만든다.**
- **롤 수를 `quantity` 에 저장하지 않는다** — `pack_size` 배(최대 130배) 어긋난다. 입력 보조일 뿐.
- **광폭 원단이 가파른 건 정상**(별도 생산구조·용준님 확인). 재료비율로 보면 손해처럼 보이는데
  단가 정책이 **「출력비 + 원자재」**라 판정 기준은 **출력마진 원/㎡**다.
- 정본 문서 = `docs/PURCHASE_RECEIVING_RULES.md`
