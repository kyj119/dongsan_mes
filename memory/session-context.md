## 결정 + 이유

- **원장 읽는 법을 바꿨다.** SmartA 는 **RealGridJS 캔버스**라 DOM 에 텍스트가 없다. 화면 스크롤로 훑다가
  **오다플래그 129M 을 「장부에 없다」고 오판**했다(실제로는 코드 008248 로 있었다).
  → `window.Grids.getActiveGrid().getDataSource()` 로 전량 직접 읽는다. 정본 = memory `reference-smarta-grid-read`.
- **껍데기 날짜는 지급일**이므로 실제 매입일로 옮겼다. 단 `E1-PO-2607-*`(월집계)는 의도된 집계라 날짜 유지 + 라인만.
- **전기이월은 `E1-PO-OPEN-<id>` @ 전년 12-31 로 분리**한다(영광 `E1-PO-OPEN-1613` 선례). 그래야 그 해 매입이 안 부푼다.
- **적요 「수량 X 단가」는 곱해서 금액과 맞을 때만 실수량**으로 넣는다. 한 품목 안에 실수량·금액전용이
  섞이면 가중평균이 오히려 틀어지므로 `docs/price/backfill_avg_cost.sql` 제외 목록에 넣는다.
- **혼재 전표(「외 n건」·「外」)는 품목을 만들지 않고 `item_id` NULL.** 원가 오염이 원천 차단된다.
- **거래처 신설 전 사업자번호로 전수조회.** 「동아디자인」=기존 `동아광고`(728), 「보영텐숀(표찰)」=기존 `보영텐숀`(1087)
  이었고 신설은 대보미싱 1곳뿐. 상호만 보고 만들었으면 2건 중복이 났다. **이름이 비슷한 「대보상사」는 딴 곳.**

## 주의사항 (다음에 같은 실수 안 하려면)

1. **통장 역산은 지급의 「하한」이다.** 상계·현금·이관기준일 이후분은 통장에 안 찍힌다(오다플래그 21.4M).
2. **매입·지급이 같은 금액으로 동시에 빠지면 AP 가 우연히 맞는다** — 잔액 대사로 절대 안 잡힌다(NTIC 6.1M·현대상사 3.7M).
3. **251 미경유 즉시결제**는 원장 잔액에도, 통장 역산에도 안 남는다(화성프로세스 792,000·우승상사 924,000).
   계정별로 펼쳐 전표를 세어야만 보인다.
4. **원장과 안 맞는다고 MES 가 틀린 게 아니다.** 계산서 지연발행 거래처는 장부가 몇 달 늦다(정운교역).
5. **entity 를 섞으면 대사가 성립하지 않는다.** 케이엠테크·서울경금속은 선명(e2) 발주가 섞여 있어 e1 만 뽑아야 맞는다.
6. 코드도움 「찾을 내용」은 **Code·거래처명만** 검색한다(사업자번호 0건). 코드는 **6자리**. 한글은 IME 가 깨진다.
