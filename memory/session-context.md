## 결정 + 이유 (코드만 봐서는 안 나오는 것)

- **`window.cardItems(card)` 접근자 = 카드 품목의 단일 소스.** 봉제 작업지시서가 **백지로 인쇄되던** 근본
  원인은 목록 API 는 `card._items`, 단건 API 는 `card.items` 로 같은 것을 다른 이름으로 주고 있었던 것.
  호출부마다 `||` 로 때우면 다음 화면에서 또 터진다 → `shell.js` 에 접근자 하나. **로컬 변수명을
  `cardItems` 로 쓰면 전역을 가린다**(한 번 당했다 · `sewItems` 로 개명).
- **`canRegenerateCards` 판정 기준을 "상태"가 아니라 "사람이 손댔는가"로 바꿨다.** 기존 조건이 PRINTING 을
  빠뜨려, **진행 중인 카드가 주문 수정만으로 파괴**됐다(체크·상태·URL·재발행 플래그 소실을 재현해서 확인).
  이제 상태·rip·print_events·체크·출력완료 중 **하나라도 흔적이 있으면 보존**하고 신규 라인만 덧붙인다.
- **자동완료 판정을 체크리스트 토글 1곳 → `maybeAutoCompleteCard` 로 추출해 3개 진입점**(토글·`/:id/status`·
  `/bulk/status`)에서 평가. 토글로만 평가하면 상태를 다른 경로로 바꾼 카드가 영원히 안 닫힌다.
- **작업지시서는 카드 기반이다**(주문 기반 아님). 혼재 주문은 **생산라인별로 카드가 쪼개지고**, 상품은
  카드 없이 `shipment_ready=1`. 실제로 4라인 혼재 주문을 만들어 카드 3장 생성을 확인했다.
  용준님 선택 = **"주문 기준 유지 + 라인별 구분"** → 한 장 안에 라인 섹션으로 나누되 상품 섹션은 맨 뒤.
- **인쇄(솔벤/UV/평판) 라인에는 봉제 필드를 안 띄운다.** 봉제방법·하도매·수술·부직포는 전사/태극기 전용.
  판정은 `card.category_name` 에 `전사`/`태극기` 포함 여부. 인쇄 라인은 **원단·규격·수량·마감·후가공·축척**만.
- **규격 표시는 품목별 1곳으로 통일**(`cd-item-size`). 우측 하단 `cd-spec-row` 의 "35x50" 이 무엇의 규격인지
  모호하다는 지적 → 제거. 용준님 지시 = "둘 중 하나로 통일".
- **기간 셀렉트 = `ordNormalizeDatePeriod` 3상태 SSOT**(프리셋 / 직접입력 / 전체). 셀렉트와 날짜가 서로 다른
