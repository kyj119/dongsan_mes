## 1. 편집 연산 3종 (실무 수정의 전부)

| 연산 | 실무 예 | 실현 방식 |
|---|---|---|
| ① 그룹 조작 | 로고 확대·위치 이동·요소 삭제·복제 | 아웃라인 무관 — ExtractGroups 그룹 단위 기하 변환. 시트배치(Tier 2) 캔버스와 동일 상호작용 |
| ② 문구 패치 | 전화번호·날짜·지점명 교체 | 아웃라인 글자는 편집 불가 → **영역 마스킹(기존 글자 가림/삭제) + 새 텍스트 생성**(제한 폰트, 크기·색·정렬 지정) → 아웃라인 변환. 디자이너 수작업의 자동화 |
| ③ 색 교체 | 바탕/글자색 변경 | 그룹 선택 → 채움색 일괄 변경 (일러 잡) |

## 2. 아키텍처 — "웹은 지시, 일러는 실행" (워크벤치 패턴 승계)

```
[수신 .ai/.eps] → 변환 잡(PNG 프리뷰, 워크벤치 P1 인프라) + ExtractGroups 그룹 메타
   ↓
[웹 편집기] Konva 캔버스 (Tier 2와 공유):
   PNG 배경 + 그룹 BBox 오버레이 → ①이동/스케일/회전/복제/삭제 ②영역지정+새문구 ③색
   실시간 프리뷰 = 캔버스 위 근사 렌더 (마스킹 박스+웹폰트 텍스트)
   ↓ 산출물
[edit-ops JSON] 연산 목록 (예시):
   [{op:"scale", group:2, factor:1.2, anchor:"center"},
    {op:"delete", group:5},
    {op:"text_patch", mask:{x_cm,y_cm,w_cm,h_cm, fill:"#FFF"|"erase"},
     text:"010-1234-5678", font:"NotoSansKR-Bold", size_pt, color, align},
    {op:"recolor", group:1, fill:"#0033A0"}]
   ↓
[IA 머지 잡] (auto_process_jobs/ai_layout 패턴): 원본 열기 → ops 순차 적용
   → 텍스트는 생성 직후 아웃라인 변환 → EPS/JPG 출력
   ↓
[검수] 워크벤치 P1 화면에서 출력 JPG 확인 → 생산 플로우 합류
```

- 원본 비파괴: ops는 DB 저장(재편집 가능), 원본 파일 불변 — 출력만 새 파일
- 미리보기↔출력 불일치 리스크: 웹 근사 렌더 vs 일러 실렌더 → **검수 단계가 게이트** (P1 재사용이라 추가 비용 0)

## 3. 데이터 모델 (초안 — 착수 시 확정)

```sql
CREATE TABLE file_edits (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ai_analysis_id INTEGER NOT NULL,      -- 원본 (분석·프리뷰 연결)
  order_id INTEGER,                      -- 연결 주문 (선택)
  ops_json TEXT NOT NULL DEFAULT '[]',   -- edit-ops 목록
  status TEXT DEFAULT 'draft' CHECK(status IN ('draft','queued','done','failed')),
  output_job_id INTEGER,                 -- 머지 잡
  output_jpg_key TEXT,                   -- 검수용 출력 프리뷰
  entity_id INTEGER NOT NULL DEFAULT 1,
  created_by INTEGER, created_at TEXT DEFAULT (datetime('now')), updated_at TEXT
);
```

## 4. 결정 확정 (2026-06-11 2차) + 잔여

| # | 항목 | 확정 |
|---|---|---|
| 1 | 마스킹 방식 | ✅ **오브젝트 삭제** (흰 박스 아님 — 기존 글자 오브젝트를 지우고 새 텍스트 배치) |
| 2 | recolor 대상 | ✅ **둘 다 (모드 선택)** — 기본 = 같은 색만 교체(파일 색 목록 자동 추출 → 색 클릭 → 새 색, 일러 '같은 칠 선택' 동일) + 그룹 전체 모드 옵션 |
| 3 | **1차 범위** | ✅ **①그룹조작 + ③색교체 완성형 + ②문구패치 단순모드** — 단순모드 = 영역(오브젝트) 삭제 + 수동 지정 크기·색 텍스트 배치 (자동 fit·정렬 고도화는 2차). 폰트 2~3종으로 시작 가능 |
| 4 | 폰트 목록 | ⏳ **용준님이 엑셀로 정리 예정** — 나오면 단순모드 폰트 셋 교체·확장. 구조(웹·일러 양측 설치 + 출력 아웃라인)는 확정 |

잔여(착수 시): scale 연산의 선폭(stroke) 보정 여부 — 현수막은 면 위주라 영향 작을 것으로 추정, P2 캔버스 작업 시 실파일로 확인

## 5. 선행 의존 / 공수

- **선행**: 워크벤치 P1 개방(검수 화면) + P2(캔버스 기술 확립) + 변환 잡 — **P2 완료 후 자연 확장**이 최적 (캔버스·잡·검수 전부 공유)
- 공수: 웹 편집기 1~2세션 + JSX ops 실행기 1~2세션 + 검수 연결 0.5세션 ≈ **3~4세션** (P2 이후 기준)
