# 품목·단가 자동계산·재고 통합 설계 (확정 north-star)

- **작성일**: 2026-06-13
- **상태**: ✅ **방향 확정 (용준님, 브레인스토밍 수렴)** — 간판 구성요소 견적은 후속(BOM)
- **목표**: ③ 전 품목 통계 + ④ 재고·원가 정확 + **단가 자동계산**. (입력 속도 개선이 아니라 "ECOUNT가 못 하던 것"을 푸는 게 목적)
- **대체**: 앞선 "4축 분리" 표현의 모호함을 정리 — 축은 *입력 항목*이 아니라 *단가표의 좌표·통계 차원*이다.

---

## 0. 한 줄 요약

**표준 품목(역할 3종) + 단가 자동계산(기본 ㎡단가표 × 거래처별 override) + 소재=자재 재고연결 + 프리셋 입력.** 축(출력방식·소재)은 작업자가 고르는 게 아니라 프리셋이 자동으로 채우고, 시스템은 그 좌표로 단가표를 찾고 통계를 낸다.

---

## 1. 품목 모델 — 역할 3종 + 표준화

| 역할(item_type) | 정의 | 예 | 단가 |
|---|---|---|---|
| 제품(PRODUCT) | 자사 출력·제조 | 현수막, 가로등배너, 깃발 7호 | 자동계산(엔진별) |
| 상품(GOODS) | 매입해 그대로 판매 | 원단째 판매, 부속품 | 매입가/정가 |
| 자재(MATERIAL) | 원자재, 재고추적 | 원단(1·2코팅/메쉬/친환경), 포맥스, 잉크, LED | 매입가 |

- **표준화 완료**: `품목마스터_확정본.xlsx` — 등록 306종(매출 98%), 나머지 393종은 ad-hoc 직접입력(`order_items.item_id=NULL` + 축 데이터 캡처)
- **겸업 물건**(원단·포맥스): 한 물건이 자재+상품+소재 → 자재(재고 단일출처) 1개 기준, 판매·소재는 그 역할 부여 (재고는 자재에서만 차감)
- **코드**: 무의미 안정코드(예: 타입1글자+순번). 카테고리·출력방식을 코드에 인코딩 금지(=축 꼬임 원인). 표시명은 축으로 자동 생성. `ecount_code ↔ 신코드` 매핑 유지

## 2. 단가 자동계산 — 엔진별 단가표

| 품목군 | 엔진 | 단가 산식 | 비고 |
|---|---|---|---|
| 현수막·출력물 | **면적형(AREA)** | 면적(가로×세로) × **㎡단가** | ㎡단가 = 단가표 조회 |
| 깃발·태극기 | **호수형(GRADE)** | 호수 → 단가 룩업 | 호수별 단가표 |
| 부속품 | **개수형(QTY)** | 개수 × 단가 | |
| 자재·상품 | 매입가/정가 | 고정 | |
| (간판) | 구성요소합(COMPONENT) | Σ 구성요소 | **후속 — BOM/별도** |

### 2.1 면적형 ㎡단가표 (핵심)
2층 구조 — **확정**:
```
기본 ㎡단가표:  출력방식 × 소재(원단)  →  ㎡단가
   솔벤 × 1코팅원단 → ₩/㎡
   UV   × 일반     → ₩/㎡        (출력방식·소재가 ㎡단가를 결정)
        +
거래처별 단가:  거래처 × 품목  →  override ㎡단가   (client_item_prices, MES 기존)
```
- 단가 우선순위: 거래처별 단가 있으면 그것, 없으면 기본 ㎡단가표
- 출력방식·소재는 **단가표의 좌표**이지 작업자 입력 항목이 아님

## 3. 재고·원가 (④)

- 자재(원단·포맥스 등) = 재고 추적, **장 단위**(면적 자동차감 미사용 — 확정)
- 제품 ↔ 자재 연결: 현수막→원단, … (원가·소요 추적용 경량 연결)
- 재고 차감: 자재 판매(상품) 또는 생산 소비 시 자재 재고에서만 차감 (단일 출처)

## 4. 입력 UX — 프리셋 (모호함 해소의 핵심)

- 작업자는 **프리셋 1클릭** ("현수막 솔벤 1코팅 열재단") → 출력방식·소재·후가공·단가가 **자동** 채워짐 → 규격·수량만 입력
- 프리셋은 **6개월 실주문 빈도에서 자동 생성** (수동 큐레이션 금지)
- 4축을 매번 고르는 UI ❌ — 프리셋 중심, 신규 조합만 축 직접 선택
- → "단가 자동계산 + 전품목 통계"를 얻으면서 입력은 ECOUNT 수준 이상으로 유지

## 5. 통계 (③)

- 품목 표준화로 **이름 일관** → 품목별 매출 정확
- 축(출력방식·소재·거래처)이 단가표 좌표로 살아있어 **출력방식별/소재별/거래처별 다차원 분석** 가능
- ad-hoc 라인도 축 데이터는 구조화 캡처 → 통계 누락 최소화

## 6. 기존 MES 활용 (버리지 않음)

| 기존 자산 | 새 역할 |
|---|---|
| `print_methods`/`print_media`/`print_method_media` | **면적형 단가엔진** — 기본 ㎡단가표 채워서 사용 |
| `client_item_prices` (0034) | 거래처별 단가 override |
| `items.item_type` + 자재/소재 연결(parent_media_id) | 역할·겸업 표현 |
| `order_items.item_id` nullable | ad-hoc 롱테일 처리 |

> 단순화 = "출력방식을 작업자 수동입력 축으로 쓰는 것"을 버린 것. 단가엔진으로서의 출력방식·소재는 **유지·활용**.

## 7. 범위 / 후속
- **1차**: 품목 표준화 등록 + 기본 ㎡단가표 + 거래처별 단가 + 자재 재고연결 + 프리셋 + 통계
- **후속**: 간판 구성요소 견적·작업지시서(별도 spec), 재고 면적차감 BOM, 역할 다중모델 정교화(= **dual 플래그 유지로 1차 해소**, B-1 검증 2026-06-19. `item_roles` 위성 승격은 단가 삼중출처 풀 때만. → [[design-item-role-multi-flag]])
