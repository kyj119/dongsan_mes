## 0. 배경 — ia-editor 심층 고찰의 결론

### 현황 진단 (사용자 확인 2026-07-16)
- **투자 대비 실사용 ≈ 0**: Export-first·네스팅·임포지션·주문연결·NAS 분석까지 prod 라이브이나, 실무는 여전히 일러 수작업 + Flexi.
- **3대 치명 제약** (사용자 선택): ① 파일이 안 열림(폰트/레거시 모달 = 헤드리스 COM hang, 사전감지 불가) ② 추출 부정확(ExtractGroups 과분할·오크롭, 보정 불가) ③ 느리고 직렬(PC 1대·일러 1인스턴스 큐).
- **공통 근원**: "헤드리스 에이전트가 무인으로 고객 파일을 연다"는 전제. 무인 열기가 실패하는 파일(레거시·폰트·대용량)일수록 실무에 자주 오는 파일 → 신뢰가 쌓일 수 없는 구조.

### 현장 사실 (설계 전제)
| 항목 | 사실 |
|------|------|
| 디자이너 | 6명, Illustrator 구독 최신버전 유지 |
| 검수 관행 | **모든 파일**을 출력 전 디자이너가 일러로 열어 확인 → 출력 방식에 맞춰 손 가공 → 정리·공유폴더 업로드 → RIP 출력 |
| 주문서 입력 | **디자이너 본인**이 직접 입력 |
| 순서 | **파일 선행, 주문서 후행**이 기본. 주문 스펙이 정확한 이유 = 파일을 보고 쓰기 때문 |
| 가공 시점 정보 | 거래처·수량은 가공 시점에 인지(메일 또는 디자인 파일 내 텍스트) |
| 처리량 목표 | 정착 시 30건+/일 |
| RIP | PDF 입력 수용 가능 (EPS 규약 단순화 카드 — 본 spec 범위 외) |
| beachhead | **모아찍기/대형** — 이것 하나가 완벽하면 주 단위 사용 시작 |

### 방향: "대체"에서 "증강"으로
열기·검수·판단 = 사람(기존 동선 그대로), 가공·파일명·정리·MES등록·주문입력 = 자동. 디자이너의 **이미 열려 있는 Illustrator 세션**에 MES를 붙인다. 헤드리스 입구는 폐기가 아닌 **보조 경로로 강등**(신규 투자 중단).

## 1. 확정 결정 (D1~D8)

| # | 결정 | 내용 · 근거 |
|---|------|------------|
| D1 | 입구 = 사람-루프 | 사람이 열면 모달=클릭 1번(hang 소멸), N세션 병렬(직렬 큐 해소). 헤드리스 업로드/NAS 분석은 보조 강등 |
| D2 | 확정 = 선택 객체 | **"선택이 곧 디자인"** — 디자이너가 선택한 객체 bbox가 디자인 영역. ExtractGroups 자동추출은 편의 기능으로 강등(과분할 문제가 '고칠 대상'이 아니라 '비존재'가 됨) |
| D3 | 가공 = 세션 즉시 | 디자이너가 오늘 손으로 하는 가공을 같은 자리·같은 시점에 자동화. **복제 문서에서 수행(원본 불가침)**. 대화형 세션 = JSX 네이티브 환경(COM group/selection 특이동작 회피) |
| D4 | 트리거 = 핫키 + 미니 선택창 | 액션 F키(Insert Menu Item로 스크립트 실행) 우선 실기 확인 → 안 되면 AHK/트레이 헬퍼 폴백. 폴백의 폴백 = File>Scripts 메뉴(첫날부터 무조건 동작) |
| D5 | 주문 연동 = 가공→대기함→주문서 프리필 | 파일 선행이 기본이므로 **가공이 주문서를 만든다**(정보 원천=파일+디자이너 판단). 주문 선행 건은 역방향(라인 선택→스펙 pull→자동 첨부)도 지원 |
| D6 | 저장 이중화 | ① 가공 완료 EPS(마감+돔보, 규약 파일명+1/N 토큰) = 단건 출력용 ② 가공 **전** 정제 work.ai(아웃라인만) = 모아찍기·재가공용. 돔보는 판 단위이므로 모아찍기 조각에는 미포함 |
| D7 | 전달 = 파일 핸드오프 | JSX는 HTTPS 불가 → `Z:` manifest 드롭 + 에이전트 ingest(기존 `IA-입력` NAS 스캔 패턴 재사용). 디자이너 PC에 인증정보 0. 에이전트 다운 시 폴더가 자연 큐(유실 없음) |
| D8 | 계측 내장 | `source=DESIGNER_SESSION` 마킹 — 등록 건수/일·디자이너별·등록→흡수 소요. **다음 실효성 고찰은 데이터로 판단** |

      ① 미니창(거래처·수량·마감)  ★신규  ├ _config 브로드캐스트 ★신규        └ 대기함 목록/지표 ★신규

## 3. 사용자 흐름

### 3.1 경로 ② — 주문 없음 (기본값)
1. 파일 열고 검수(기존, 모달도 평소처럼 클릭)
2. 디자인 객체 선택 → 핫키 → **미니창**: 거래처(자동완성)·수량·마감 프리셋·돔보·배율(1/N) 입력, 실측 크기 자동 표시 → [가공 실행]
3. 자동: 복제 문서 → 마감·돔보·배율 적용 → 아웃라인 → 규약 파일명 EPS + 정제 work.ai + 썸네일 저장 → 공유폴더 → manifest 기록
4. 에이전트: manifest ingest → **대기함 등록**(거래처·실측·마감·수량·썸네일·파일 경로)
5. 디자이너가 주문서 작성 시: 거래처 선택 → "가공 대기물 N건" 배지 → 클릭 → **라인 자동 채움**(크기·마감·수량·파일·썸네일 프리필) → 품목·단가만 확인 → 저장

### 3.2 경로 ① — 주문 선행 (역방향)
미니창 상단 "미가공 주문 라인" 목록에서 선택 → 라인 스펙(크기·마감)대로 자동 가공 → 해당 라인에 자동 첨부(기존 직접연결 D 경로 `ai_analysis_id` + group_index -1/-3).

### 3.3 모아찍기 (beachhead)
등록된 정제 work.ai들이 `/ia-editor` 임포지션 팔레트에 등장(기존) → 판 구성 → 서버 SheetLayout 렌더. **서버가 여는 파일은 정제 work.ai뿐 → hang 없음.**

### 3.4 후가공 커버리지 — 3계층 (검토 반영 2026-07-16)
"핫키로만 다 하는" 구조가 아님 — **핫키는 미니창을 여는 트리거**이고, 후가공 선택지는 미니창 안에 있음:

| 계층 | 방식 | 커버 범위 |
|------|------|----------|
| 1. 무다이얼로그 매크로 (선택 사항) | 최빈 프리셋 2~3종만 전용 핫키 — 창 없이 즉시 적용, MES 미관여 | 반복 최다 케이스의 속도 |
| 2. 미니창 (기본 경로) | 마감 **프리셋 드롭다운**(웹 인스펙터와 동일한 `finishing_methods/presets` 데이터) + **[상세 ▸] 확장**: 4면(상/하/좌/우) 개별 지정·여백 cm 직접 입력 + 돔보·배율 | 정형 후가공 전부 |
| 3. 수작업 에스케이프 (구조 내장) | 진짜 특수건은 디자이너가 일러에서 **그대로 손 가공** 후, 미니창에서 마감="없음(수동 완료)"으로 등록만 | 나머지 100% |

계층 3이 사람-루프 구조의 내장 장점: **도구가 모든 후가공을 커버할 필요가 없음** — 디자이너가 이미 Illustrator 안에 있으므로, 도구가 못 하는 가공은 언제나 손으로 하고 등록·주문연동 혜택만 취하면 됨. (헤드리스 구조에선 불가능했던 탈출구)

## 4. 상세 설계

### 4.1 디자이너 측 (JSX)
- **부트스트랩**: 로컬 스텁 1파일(설치 1회) → `$.evalFile('Z:\\DESIGNS\\IA-등록\\_scripts\\mes-core.jsx')` 정본 로드. **중앙 1곳 수정 = 6대 즉시 반영** (JSX 수동 동기화 함정 재발 방지). manifest에 script_version 스탬프.
- **가공 코어**: `ProcessOrderItem.jsx`의 마감(4면 per-side)·돔보(CORNER_DIST 17mm)·배율(÷scale) 로직 이식. **상수 단일소스** = 공유 모듈(서버 jsx와 이원화되는 상수는 정기 대조 체크리스트에 등재).
- **원본 불가침**: 선택 객체를 새 문서로 복제 후 모든 처리. 열려 있는 고객 파일은 무변경.
- **아웃라인 우아 강등**: 잠긴 레이어·특수 객체로 실패 시 "그대로 저장 + manifest에 `outline_failed:true`" (막지 않고 표시).
- **파일명 규약**: 기존 `FormatScaleToken` 규약 동일 이식 — `{날짜}-{거래처}-{WxH}-{수량}EA(_1-N).eps` (대기 상태, §9-1 검토). 1/N 토큰 = RIP ×N 확대 규약 유지.

### 4.2 파일 핸드오프 (Z:)
```
Z:\DESIGNS\IA-등록\
├ _scripts\mes-core.jsx            # 정본 스크립트 (부트스트랩 로드 대상)
├ _config\presets.json             # 마감 프리셋 (에이전트가 주기 기록)
├ _config\clients.json             # 거래처 목록 스냅샷
├ _config\orders-open.json         # 미가공 주문 라인 (경로①용)
├ {yyyyMMdd_HHmmss}_{PC명}_{seq}\  # 건별 폴더 (유니크)
│  ├ work.ai / output.eps / thumb.jpg
│  └ manifest.json                 # ★마지막에 기록 = 커밋 신호
└ done\… (ingest 완료분 이동)
```
- **커밋 마커**: 파일 저장 완료 후 manifest를 마지막에 기록. 에이전트는 manifest 있는 폴더만 처리 → 반쯤 쓰인 파일 읽기 원천 차단.
- **멱등**: 처리 후 폴더를 `done\`으로 이동(또는 `.ingested` 마커). 재스캔 시 중복 등록 없음.
- **manifest 스키마 (v1)**:
```json
{
  "manifest_version": 1, "script_version": "0.1.0",
  "registered_by": "PC명\\사용자", "entity_id": 1,
  "client_name": "동산상사", "qty": 2,
  "finishing": {"top":"아일렛","bottom":"아일렛","left":"재단","right":"재단"},
  "trim": true, "scale_pct": 100,
  "measured_cm": {"w": 512.3, "h": 92.1},
  "mode": "single|impose|both",
  "order_item_id": null,
  "files": {"work_ai": "work.ai", "eps": "output.eps", "thumb": "thumb.jpg"},
  "outline_failed": false,
  "created_at_kst": "2026-07-16 14:30:22"
}
```

### 4.3 에이전트 (C# — 기존 확장)
- **ingest 폴러**: 기존 `IA-입력` 스캔 패턴 미러 — 폴 주기마다 `IA-등록\*\manifest.json` 발견 → MES API 등록(에이전트 기존 서비스 JWT) → `done\` 이동. 실패 시 폴더 잔존 = 자연 재시도.
- **등록 내용**: ① `ai_analysis_requests` 생성(status=done, `groups_json`=[{썸네일 base64, 실측}], file_path=work.ai Z:경로 — 서버 렌더 `ResolveSourceAiAsync`가 로컬 해석 가능) ② `designer_intakes` 레코드(§4.4). `order_item_id` 있으면(경로①) 직접연결 첨부까지.
- **설정 브로드캐스트**: 폴 N주기마다 `_config\*.json` 갱신 (presets=`finishing_methods/presets`, clients, orders-open=미가공 CONFIRMED 라인).

### 4.4 서버/웹 (Workers + 마이그레이션)
- **신규 테이블 `designer_intakes`** (권장, §9-2 검토): `id, entity_id, ai_analysis_id FK, client_name, client_id(매칭 시), qty, finishing_json, width_cm, height_cm, scale_pct, trim, mode, eps_path, work_ai_path, status(waiting|absorbed|void), order_item_id, registered_by, pc_name, script_version, outline_failed, created_at, absorbed_at`. `ai_analysis_requests` 스키마는 무변경(드리프트 위험 회피).
- **API**: `POST /api/workbench/intakes`(에이전트 등록) · `GET /api/workbench/intakes?client=&status=waiting`(대기함) · `POST /api/workbench/intakes/:id/absorb`(주문 라인 연결, status 전이) · void(취소). entity 격리 + `requirePagePermission` 기존 패턴.
- **주문서 UI**: 거래처 선택 시 대기물 배지("가공 대기물 3건") → 피커 모달 → 선택 → 라인 자동 채움(크기·마감·수량·`ai_analysis_id`·썸네일). 품목·단가는 기존 라인 UI에서 확인. 기존 직접연결(D2 itemRow '파일 연결') 배선 재사용.
