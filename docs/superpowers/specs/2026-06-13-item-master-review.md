## A. 마스터 확정 (직접 판단)

### 확정 사항
| 항목 | 확정 |
|---|---|
| 대분류 | 현수막·배너·깃발·기·간판·시트·스티커·판재출력·출력물·부속품·원자재·비품목 |
| 현수막 | **단일 품목(제품)** — 인쇄방식/원단/후가공/공정어 모두 흡수 (9.3억) |
| 원단(1·2코팅·메쉬·친환경) | 후가공 ❌ → **소재축**. 자재/소재/상품 3역할 (포맥스식) |
| 비품목 | 할인·이월금액·시안비·장비 등 → **품목 제외**(금액조정/서비스) |
| 역할 | 제품/상품/원자재, 원단류는 겸업 |

### 핵심 확정: 80/20 등록정책
- **등록 306종 = 매출 98%**, 나머지 393종(1~2회성)은 **ad-hoc 직접입력**으로 강등
- 700종을 다 등록하면 마스터가 노이즈로 폭발 → 반복품목만 정식 등록, 1회성은 `order_items.item_id=NULL`(이미 지원) + 축 데이터만 구조화 캡처
- 확정본 엑셀: 회색 행 = ad-hoc 후보, 흰 행 = 등록 대상

## B. 구조 비판 리뷰 — "더 나은 구조" (독립 검토 종합)

방향 자체(단일 items + 다축, 비파괴 (나)→게이트→(다))는 **운영 리스크상 옳다.** 단 아래는 이 방향이 숨긴 함정이다. 위험도순.

### 🔴 B-1. 역할(item_type) 단일 enum이 "겸업 물건"에서 깨진다 — (다) escalate 1순위
원단·포맥스는 **동시에** 자재(소비)·상품(생판매)·소재(면적출력 단가요소)다. 그런데 `item_type`은 **배타적 단일 enum**. 한 물건에 다중 역할을 단일 값으로 못 담는다.
- 함정: 재고 이중장부(상품판매 차감 ↔ BOM 차감이 서로 안 비침), 단가 삼중출처(매입가/판매가/㎡소재단가)
- **역설**: realign이 "제거 대상"으로 본 `is_sales_item`/`is_purchase_item` **다중 플래그가 사실 다중역할에 더 맞았다.** 0093이 단일 enum으로 합친 게 회귀일 수 있음
- **권고**: 역할을 item *속성*이 아니라 *관계*로. items 1행=물리·재고 단일 진실, 역할은 `item_roles` 위성(플래그 셋 + 역할별 가격). → **realign Phase 2 "item_type 단일출처화"는 겸업 물건에서 정보손실. 이 항목이 게이트에서 (다)로 가는 1순위 트리거.**
> ✅ **검증·결정 (2026-06-19, prod)**: 겹업물건 다수 입증 — prod 63/103 다중역할, **MATERIAL 53건이 is_sales_item=1**(자재겸판매). 단 현재 dual 플래그가 다중역할을 이미 표현 → **전면 재설계(다) 불요. 결정 = realign Phase 2 collapse만 삭제, dual 플래그 유지가 역할 정본**(옵션 A). 단가 삼중출처 해소 시점에만 `item_roles` 승격(옵션 B). → [[design-item-role-multi-flag]]

### 🔴 B-2. 빠진 단가 엔진 2개 — 깃발(호수)·간판(템플릿)
`pricing_method`가 `FIXED|AREA`뿐. 그런데:
- **깃발·태극기 = 호수별 룩업(GRADE)** — 면적도 정액도 아님. FIXED로 우기면 호수마다 별도 품목(롱테일 폭발), AREA면 틀림 → `size_grade_prices` 룩업 필요
- **간판 = 재사용 견적 템플릿** — 현 설계(§2.3)는 견적값을 order_items 자식라인에 박아 **재사용 템플릿이 안 만들어짐**. 농협 채널간판 매번 12줄 손입력 → B-3 직결. "채널간판=채널+LED×ea+SMPS+알루미늄바+까치발×ea 빈칸채움" 파라메트릭 템플릿 레이어 필요
- **권고**: items=얇은 헤더 + 아키타입별 단가 위성(plug-in). 빠진 두 엔진을 1차 범위에 포함

### 🔴 B-3. 작업자 입력 UX — 가장 과소평가된 리스크
모델 정합성만 보고 **매일 입력 마찰을 안 다룸**. 4축 매번 드롭다운 + 700종 목록 = 작업자가 "기타"에 때려넣거나 옛 통금액으로 회귀.
- 9.3억이 소수 조합에 몰린 80/20 = 매일 쓰는 조합은 20~40개
- **권고**: `item_presets`(즐겨찾기)를 데이터모델과 **동급 1급 시민**으로. "현수막 솔벤 1코팅 열재단"=1클릭 프리셋, 규격·수량만 입력. **실주문 빈도로 자동 생성.** 다축분리=백오피스/MRP 진실, 작업자UI=프리셋 중심으로 **비대칭 설계** 명시 (안 하면 구현팀이 4드롭다운 UI 만들고 현장에서 죽음)

### 🟠 B-4. 솔벤 = 인쇄방식 vs 원단 — 잔존 혼동
`print_methods`엔 솔벤=인쇄방식(0154), `category` TEXT엔 솔벤=분류(0006) 중복. 현장 용어는 방식·소재가 한 단어. 게다가 items가 print_method_id/media_id를 **직접 FK로 참조** → "솔벤×포맥스" 같은 무의미 조합 가능(연결테이블 우회).
- **권고**: items 직접 FK 대신 **`print_method_media_id` 단일 FK**(유효조합만 선택). 현장용어는 프리셋 라벨로 흡수(B-3 연계)

### 🟠 B-5. 롱테일 정책 (위 A에서 확정 반영)
"기타 335종"은 정식화 대상이 아니라 **대부분 ad-hoc 강등 대상.** 확정본에서 등록 306/ad-hoc 393으로 갈라 반영 완료. 단 ad-hoc도 인쇄방식·소재·면적은 구조화 캡처해야 MRP·정산이 삼.

### 🟡 B-6. 단가 다형성이 암묵적
`pricing_method`별로 어떤 컬럼이 유효한지(AREA=width/method, COMPONENT=sign_component) **스키마가 강제 안 함** → 컬럼 30개 중 절반이 행마다 NULL, 합법조합은 앱코드에만. "축 꼬임"의 출처.
- **권고**: 암묵적 NULL 컬럼 → **명시적 태그드 유니온**(pricing_profile 디스크리미네이터 + 프로파일별 유효 위성 문서·CHECK 명시)

## C. 종합 권고 — "내가 설계자라면" 3개

1. **역할을 다중관계로** (최우선): `item_type` 단일 enum → `item_roles` 위성(다중 플래그+역할별 가격). 원단·포맥스 겸업 물건의 정보손실·재고이중장부 방지. **realign Phase 2 직전 게이트에서 이 항목으로 (다) escalate 판단.**
2. **단가 다형성을 명시적 plug-in 엔진으로 + 빠진 2엔진(호수 GRADE, 간판 견적템플릿) 1차 포함.** 안 하면 깃발=롱테일, 간판=입력마찰로 터짐.
3. **프리셋 레이어를 1급 시민으로 + 롱테일은 ad-hoc 라인으로.** 80/20 자동 프리셋으로 4축 1클릭화, 솔벤 같은 축혼동도 프리셋이 흡수. 반복품목만 마스터, 1회성은 item_id NULL.
