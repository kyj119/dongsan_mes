## 0. 이 문서의 근거 — 그리고 근거가 **아닌** 것

재설계는 근거를 잘못 잡으면 방향 전체가 틀어진다. 그래서 무엇을 근거로 쓰지 **않기로** 했는지를 먼저 적는다.

### 0.1 철회 — "실사용 0 = 거절"로 읽지 않는다

`designer_intakes` 실측(prod, 2026-08-26):

| | 등록 | PC | 마지막 |
|---|---|---|---|
| 재단 탭(`CUT-*`) | 5 (전부 `void`) | 개발 PC 하나 | 08-05 |
| 가공 탭(`A0-*`) | 106 | 개발 PC 102 · 디자이너 PC 2대(각 **하루**) | 08-10 |

**이 숫자를 채택 실패의 증거로 쓰지 않는다.** 원인은 배포다(용준님 확인) — 축4는 PC별 수동 설치라 디자이너 PC의 셸은 8/6 시점에 멈춰 있다. 도달한 적이 없는 것을 거절당했다고 읽으면 엉뚱한 것을 고치게 된다.

### 0.2 철회 — 완성 파일로 **과정**을 규명하지 않는다

완성 EPS/DXF 는 **결과**만 담는다. 칼선을 손으로 그렸는지 내보냈는지, 마감 여백을 손으로 늘렸는지, 어느 단계가 얼마나 걸렸는지 — 전부 안 나온다. 그러므로 아래 §1 은 **코드가 증언하는 결함**만 담고, 파일 실측은 §3(결과물 검증 = 파일이 정당하게 답할 수 있는 질문)에만 쓴다.

### 0.3 채택하는 근거

- **용준님 진술** — 시간이 오래 걸리는 순서 = **판짜기 > 돔보 배치 > 칼선 제작**, 그리고 후가공(파일 가공).
- **코드** — 아래 결함 A~D 는 사용 여부와 무관하게 소스에 있다.
- **결과물 검증** — 배율 분포·후가공 여백 반영 여부처럼, 완성 파일이 **결과로서** 답할 수 있는 것만.

## 1. 확인된 결함 (코드 근거)

### 1-A. 배포 축이 사람 손이다 — **1순위**

CLAUDE.md 의 5축 중, 셸만 중앙 배포가 아니다.

| 축 | 갱신 방법 | 전 PC 반영 |
|---|---|---|
| 축2 호스트 JSX | `Z:\DESIGNS\IA-등록\_scripts\` **1개 교체** | **즉시** — `mes-bootstrap-stub.jsx` 가 `$.evalFile` 로 Z: 를 읽는다 |
| 축3 셸 배포본 | Z: 갱신 | 반영 안 됨 |
| **축4 설치본** | **PC 방문 → `install-a0-panel.ps1`** | **PC 수만큼 손** |

축4 가 일러가 실제로 읽는 것이다. 즉 **셸은 고쳐도 도달하지 않는다.** UI 를 아무리 잘 고쳐도 이 축이 사람 손이면 개선이 사용자에게 닿지 않고, 닿지 않으면 피드백도 없고, 피드백이 없으면 다음 개선의 방향도 알 수 없다. 흐름 문제의 뿌리는 화면이 아니라 여기다.

**이미 풀린 문제라는 점이 중요하다** — 축2 가 정확히 그 방식으로 돌고 있다. 셸만 안 하고 있을 뿐이다.

### 1-B. 같은 값을 묻는 칸이 두 곳

| 값 | 단품 칼선 | 판짜기 |
|---|---|---|
| 오프셋/여백 | `index.html:262` `offset` | `index.html:370` `nestOffset` |
| 도련 | `index.html:268` `bleed` | `index.html:383` `nestBleed` |

`index.html:256` 주석이 스스로 적고 있다 — *"두 곳에 오프셋·도련 칸이 따로 있어 '어느 칸을 고쳐야 하나'가 반복 질문이었다"*. 제목에 적용 범위를 못박는 것으로 완화했을 뿐 원인은 남아 있다.

### 1-C. 배율이 산출물에 남지 않는다

`cutScaleFile`(파일이 실물의 1/F) · `cutScale`(1/S 로 저장)을 손으로 고르고, 계산에 쓰고, **버린다**. 파일에도 manifest 에도 남지 않는다. 그래서 뒤에서 아무도 검증할 수 없다.

`index.html:430` 이 이 위험을 경고문으로만 처리하고 있다 — *"저장 배율을 낮추면 돔보·칼선도 작아짐 — 반드시 파일명 규격대로 확대 출력해야 재단기가 돔보를 읽습니다."* 경고는 사람이 지키는 것이고, 지켜졌는지 확인할 수단이 없다.

### 1-D. 두 탭이 같은 곳으로 가는데 폼이 다르다

가공 탭 등록과 재단 탭 등록은 **동일한 `Z:\DESIGNS\IA-등록\<건별>\manifest.json` 경로**로 간다(`mes-a0-host.jsx` · `mes-cut-host.jsx:2760~`). 그런데 입력 폼이 서로 다르다 — 가공은 거래처·수량·가공자·주석, 재단은 거래처·수량·가공자·자재·후가공·품목. 같은 결과를 만드는 두 개의 다른 문법을 배워야 한다.

## 2. 결함 A 해법 — 5축을 2축으로

**축2가 축3/4를 갱신하게 한다.** 축2 는 이미 중앙이므로, 축2 한 곳만 바꾸면 셸까지 따라온다.

```
일러 부팅 → 패널 열림 → 셸이 host 에 mesPanel_syncShell() 호출
                              ↓
        호스트(Z: 정본, 이미 전 PC 최신)가:
          Z:\...\_scripts\a0-panel\com.mes.a0.panel\VERSION
          %APPDATA%\Adobe\CEP\extensions\com.mes.a0.panel\VERSION  비교
                              ↓
        다르면 → 설치본 백업 → Z: → 설치본 복사 → 'updated;from=..;to=..' 반환
                              ↓
        셸이 결과창에 "패널이 갱신됐습니다 — 일러를 다시 켜 주세요" 표시
```

- 복사는 ExtendScript `File.copy()` / `Folder` 순회로 한다. 셸의 `window.cep.fs` 도 가능하지만(패널이 이미 `readFile`/`writeFile` 을 쓴다 — `cut-main.js:393`·`:1972`), **호스트에 두는 편이 낫다** — 셸이 자기 자신을 덮어쓰는 순환을 피하고, 축2 하나만으로 완결된다.
- **일러 재시작 방식으로 확정**(용준님 2026-08-26). 갱신을 감지하면 복사하고 `"패널이 갱신됐습니다 — 일러를 다시 켜 주세요"` 를 결과창에 띄운다. 패널 재오픈만으로 되는지는 따지지 않는다 — 재시작을 요구하면 **동작이 한 가지로 고정**되고, CEP 캐시 상태에 따라 반영이 갈리는 회색지대가 없어진다. 관리자가 PC 를 도는 것과 비교하면 이미 다른 세계다.
- **롤백** = Z: 정본을 되돌리면 다음 부팅에 전 PC 가 되돌아온다. 지금은 PC 를 다시 돌아야 한다.
- ⚠️ 자동 복사가 **작업 중인 패널을 덮어쓰면 안 된다** — 부팅 시 1회만, 그리고 `hostBusy` 가 아닐 때만.
- `npm run audit:ia-jsx` 의 드리프트 판정은 그대로 둔다. 자동 동기화가 생겨도 **repo↔Z: 드리프트**는 여전히 사람이 만드는 것이다.

## 3. 결함 C 해법 — 배율 자동 판정

### 3.1 재는 방법

파일을 뜯지 않는다. **판짜기·칼선 시점엔 문서가 일러에 열려 있다** — 아트보드/선택 bbox 를 직접 잰다(`mesCut_docInfo` · `mesCut_selectionInfo` 이미 존재).

```
규격  = 파일명에서 파싱한 (W x H)  — 실물 cm
실측  = 아트보드 우선, 없으면 선택 bbox — cm
```

### 3.2 여백과 배율을 가르는 것이 핵심

내가 8월 767건에 순진한 규칙을 돌렸더니 53건이 걸렸는데 **상당수가 실제로는 미싱 여유였다**. 완성 파일만 보면 이 둘을 못 가른다. 패널 안에서는 가를 수 있다 — 여백 값이 마감 표에 **입력돼 있기 때문**이다.

| | 배율 | 후가공 여백 |
|---|---|---|
| 가로·세로 | **항상 같은 비율** | **변별 비대칭**(상하만·좌우만이 흔함) |
| 값 | {1, 2, 4, 5, 10} 에 붙음 | 임의 (3·4·5·9cm…) |
| 패널이 아는가 | 모름 → 판정 대상 | **마감 표 입력값 → 빼고 잰다** |

### 3.3 판정 규칙

```
rw = 규격W / (실측W − 여백좌 − 여백우)
rh = 규격H / (실측H − 여백상 − 여백하)

① |rw − rh| / max(rw,rh) > 2%
     → "규격과 파일이 안 맞습니다 (W 1/10.0 · H 1/1.0)"  — 배율 판정 불가, 진행 정지
② N = 최근접 {1, 2, 4, 5, 10},  avg = (rw+rh)/2
   |avg − N| / N > 3%
     → "비표준 배율 1/2.49 — 확인하세요"  — 값은 avg 로 두고 확인 요구
③ 아니면 N 확정, 조용히 채운다
```

- `(3100x111)` → 실측 310×111 = W비율 10 · H비율 1 → **①이 잡는다.** 이건 배율 오류가 아니라 **파일명의 mm/cm 혼용**이고 그렇게 말해야 맞다.
- **파일명에 규격이 없으면 판정하지 않는다** — 8월 767건 중 63건(8%)이 그렇다. 조용히 1/1 로 가정하지 말고 **손입력 칸을 남긴다**.
- 판정 결과는 **manifest 에 기록한다**(`scale_pct` 는 이미 있다). 결함 C 의 본체는 "안 남는다"이므로, 자동 판정만 하고 안 남기면 절반만 고친 것이다.

### 3.4 이 규칙이 잡지 못하는 것 (명시)

- 아트가 아트보드보다 크거나 작게 저장된 경우 — **아트보드 우선**으로 정의해 흔들림을 없애되, 아트보드가 아트와 크게 다르면 그 자체를 경고한다.
- 규격 표기가 실물이 아니라 완성 후 크기인 경우(미싱 접은 뒤 치수). 여백을 알면 보정되지만, 마감 표를 안 채우고 판짜기만 하면 못 잡는다.

## 6. 후가공은 유지한다 — 대체 불가

후가공은 메타데이터가 아니라 **파일을 실제로 뜯어고치는 기능**이다. `mes-a0-host.jsx`:

| 동작 | 위치 |
|---|---|
| 아트보드를 변별 여백만큼 **확장** | `:459` |
| 체크한 변의 디자인 경계에 **K100 실선**(재단선) | `:466~478` |
| 여백 바깥 **백색 0.5pt**(RIP 출력영역 확보) | `:483~493` |
| 여백 위치에 **마감 재단선**(그룹 `마감재단선`) | `:497~518` |

프리셋·방식은 MES 에서 이미 브로드캐스트된다(`_config/config.json` — `methods` 9종 · `presets` 11종 · `workers` · `clients` 2,873). 파일명이 `사방접어미싱` 이라고 **말할 수는** 있어도 이 네 가지를 **대신하지는 못한다.**

결과물 검증(§0.2 가 허용하는 범위) — 8월 미싱·조립류 104건 중 **65건(63%)이 표기 규격보다 실제로 크다** = 여백이 파일에 들어가 있다. 이 일이 실제로 벌어지고 있다는 사실만 말하며, **누가 어떻게 넣었는지는 파일이 답하지 못한다.**


`cards.rip_filename` 은 **디자인 파일명이 아니라 TNS RIP 잡 이름**이다 — `rip.ts:1490` `C:\TNSRip-X11\Job\${card.rip_filename}.job`. 파일명 경로에 등장하지 않으므로 자릿수는 애초에 부딪히지 않는다.

⇒ **`resolveCard` 를 넓히지 않는다.** 넓히면 `(?!\d)` 가 막던 오매칭(`-0011` 에서 `001` 오려내기)만 열린다. 얻을 것 없이 잃는 변경이다.

### ③ 소요 시간 → **판짜기 최우선 확정**

용준님 실측 = **시트 10조각 배치 ≈ 20분**, 일반 현수막 후가공의 **약 10배**.
⇒ 판짜기가 패널이 줄일 수 있는 **가장 큰 단일 항목**이다. §5 우선순위 확정.

**빈도 확정(2026-08-26 재측정)** — 앞선 두 측정(10% vs 43%)이 갈린 이유를 찾았다: **일러 DXF 는 도형을 `BLOCKS` 에 넣고 `INSERT` 로 참조한다.** 두 파서 모두 `ENTITIES` 만 읽어 **칼선을 통째로 못 봤다.** 블록을 풀고 다시 세면:

| 월(자체 제작분·두용 외주 제외) | DXF | 2조각+ | 7조각+ | 조각 총합 |
|---|---|---|---|---|
| 2026-07 | 197 | 76 (39%) | 28 (14%) | 2,200 |
| 2026-08 | 142 | 43 (30%) | 17 (12%) | 518 |

영업일 환산 = **2조각+ 하루 약 3건 · 7조각+ 하루 약 1.2건**.
20분/10조각을 적용하면 **하루 35~40분 · 월 12~15시간**.

⚠️ 이건 **재단 DXF 가 나온 건만**이다. 인쇄 전용 판짜기(RIP 가 하는 것)는 세지 않았다 — 즉 **하한**이다.
⚠️ 파서 함정을 기록해 둔다: `INSERT`/`BLOCKS` 를 안 풀면 조각 수가 **0~1 로 보인다**. DXF 를 셀 일이 또 생기면 이것부터 확인할 것.

### ④ 폴더·순번 자동화 → **중복을 줄이는 게 아니라 방향을 뒤집는다**

먼저 전제 실측 — **현장 카드는 아직 돌지 않는다.**

| 테이블 | 행 수 |
|---|---|
| `cards` · `card_items` · `work_records` · `production_logs` | **전부 0** (8월분은 `_bak_0813_aug_cards` 488건으로 백업 이동) |
| `orders` / `order_items` | 10,074 / 23,162 · 마지막 `order_date` **2026-07-31** |

⇒ **중복은 아직 발생하지 않았다.** 파일명만 손으로 적고 카드는 비어 있다. 줄일 중복이 없고, **지금이 설계로 막을 수 있는 위치**다.

| 정보 | 파일명 | 카드 | |
|---|---|---|---|
| 순번·거래처·품목·규격·장수·자재·후가공·납기 | 전부 있음 | `client_name`·`item_name`·`width`/`height`·`quantity`·`post_processing`… | 겹침 |
| **주문/카드 키** | **없음** | `card_number` | ⚠️ **유일한 비겹침 — 이것이 없어서 매칭 0%** |
| 배율 | 없음 | 없음 | 양쪽 다 없음(§3) |

**판단 ①: 파일명에서 정보를 빼지 않는다.**
RIP 오퍼레이터와 재단 담당은 MES 화면이 아니라 **파일명을 보고 일한다**. 짧게 만들면 그 사람들이 MES 를 봐야 하고, 그건 비용을 줄이는 게 아니라 옆으로 미는 것이다. 중복 자체는 문제가 아니었다 — **키 부재**가 문제였다.

**판단 ②: ~~카드가 파일명을 만든다~~ → 흐름이 반대다(2026-08-26 용준님 정정).**

용준님 진술 = **"일러스트에서 가공을 한 이후에 주문서를 작성하는 게 맞다."**
⇒ 저장 시점에 **주문번호가 아직 없다.** "카드 → 파일명 파생"은 성립하지 않는다.

그리고 그 흐름은 **이미 설계돼 있다** — 패널 등록 → `designer_intakes(waiting)` → 주문서에서 흡수 → `order_item_id` 연결(`workbench.ts:925`). 파일이 먼저고 주문이 나중이다.

⇒ **키는 앞에서 심는 게 아니라 뒤에서 붙인다.** 흡수 시점에는 「파일」과 「사람이 고른 주문 라인」이 **둘 다** 있다. 그때 `print_file_map` 에 학습시키면 이후 `resolveCard` 2차(파일명 일치)가 해소한다.

**선례가 같은 엔드포인트에 이미 있다** — 흡수 시 **거래처 별칭 학습**(`workbench.ts:934~961`). 주석까지 같은 논리다: *"흡수 시점에는 「파일 표기」와 「사람이 고른 거래처」가 둘 다 있다 — 그때 붙여 둔다."*

⚠️ **다만 지금 당장은 못 한다.** intake 가 아는 파일명은 등록 폴더의 `거래처-WxH-NEA-nest.eps` 인데, RIP 가 보는 것은 작업 폴더의 **손저장 이름**(`33-애니룩스-…`)이다. **둘을 잇는 것은 패널의 「작업 폴더로 내보내기」뿐**이다(`mesCut_exportPair` 가 실물 규약대로 이름을 짓는다).
⇒ **매칭 복구도, 카드도, 파일명도 전부 「패널이 실제로 쓰인다」에 걸려 있다.** 그래서 §2(배포 축)가 1순위인 것이 재확인된다.

**판단 ④: 패널은 폴더·순번을 지어내지 않는다. 카드에서 받아온다.**
패널이 독립 채번하면 **그때 비로소 진짜 이중 규명이 생긴다**. §4 의 "등록 폼 공용 한 벌"도 같은 이유 — 폼이 카드를 대신 만드는 게 아니라 **카드를 고르는 것**이어야 한다.

⚠️ 다만 카드가 0건인 지금은 **폴백이 반드시 필요하다** — 카드가 없으면 지금처럼 손 파일명으로 저장되고, 그때는 키가 없다. 키 없는 저장을 막지 말고 **키 없음을 표시**한다(조용한 실패 금지).

## 8. 하지 말 것

- **후가공 마감 표를 파일명 파싱으로 대체** — §6. 파일명은 지시를 적을 뿐 기하를 바꾸지 않는다.
- **네스팅을 접거나 지우기** — 시간 최다 항목이다(§5).
- **자동 판정이 실패했을 때 조용히 기본값으로 진행** — 배율 판정 불가는 정지시킨다(§3.3). `feedback-silent-catch-shape-mismatch` 재발 금지.
- **셸 자동 갱신을 작업 중에 실행** — 부팅 1회, `hostBusy` 아닐 때만(§2).
- **`audit:ia-jsx` 를 자동 동기화가 생겼다고 완화** — repo↔Z: 드리프트는 여전히 사람이 만든다.
- **디자이너 PC 를 손으로 도는 것을 전제한 설계** — 그게 결함 A 다.
- **파일명을 짧게 만들어 정보를 카드로만 밀기** — RIP·재단 담당에게 비용을 전가한다(§7-④ 판단①).
- **패널이 순번·폴더를 독립 채번** — 카드와의 이중 규명을 **새로 만드는** 짓이다(§7-④ 판단④).
- **`resolveCard` 정규식을 넓히기** — 실제 파일명은 이미 3자리라 부딪히지 않는다. 넓히면 `(?!\d)` 가 막던 오매칭만 열린다(§7-②-a 철회).
- **DXF 조각 수를 `ENTITIES` 만 읽고 세기** — 일러는 도형을 `BLOCKS`+`INSERT` 로 내보낸다. 안 풀면 **전부 0~1 조각으로 보인다**(§7-③에서 두 번 틀렸다).
