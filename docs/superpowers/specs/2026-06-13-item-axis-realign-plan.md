## 0. 설계 원칙 — (나)는 (다)의 온램프

핵심: **(나)의 모든 단계를 "비파괴(additive)"로 설계**한다. 컬럼 삭제·되돌리기 어려운 변경은 **결정 게이트 이후 마지막 Phase로 미룬다.** 그러면 중간에 (다)로 갈아타도 잃는 작업이 최소다 (정제된 분류·역할 모델·audit은 재설계에서도 그대로 재사용).

## 1. North-star — 깨끗한 5축 모델 (개념은 안 꼬임)

| 축 | 의미 | 값 예시 | 물리 표현(목표) |
|---|---|---|---|
| ① 분류(제품종류) | 무엇 | 현수막·배너·깃발·간판·시트·판재출력·현판·부속품 | `category_id`(FK) **단일** |
| ② 인쇄방식 | 어떻게 출력 | 솔벤·수성·UV·전사·평판·친환경 | `print_method_id` **단일 출처** |
| ③ 후가공/마감 | 마감 처리 | 코팅·열재단·미싱류 | post_processing / finishing |
| ④ 역할 | 매출/매입/재고 | PRODUCT·MATERIAL·GOODS | `item_type` **단일 출처** |
| ⑤ 자재(재고 원천) | 물리 재고 | 포맥스 원판(장) | MATERIAL item + parent_media_id |

원칙: **한 정보는 한 곳에만.** 지금은 ①②④가 두세 곳에 중복 인코딩돼 있어 "축이 꼬인" 느낌이 나는 것.

## 2. 정렬 대상 (audit 결과 — 위험도순)

| 꼬임 | 현 상태 | 목표 | 위험 |
|---|---|---|---|
| 분류 ↔ 카테고리 텍스트/FK 이중 | `category`(TEXT) + `category_id`(FK) 공존, inventory는 TEXT·items는 FK로 따로 씀 | `category_id` 단일, TEXT는 파생(읽기 응답용) | **상** (쿼리 분산, 조인 추가) |
| 역할 이중 인코딩 | `item_type` + `is_sales_item`/`is_purchase_item` 동시 존재 (0093서 변환했으나 플래그 잔존) | `item_type` 단일 출처, 플래그는 파생 | **상** (routes 8곳, migration) |
| 인쇄방식 이중 | 카테고리에 '솔벤·UV·전사' + `print_method_id` | 카테고리에서 인쇄방식 제거(②로) | **중상** |
| 소분류 이중 | `subcategory_id`(FK) + `sub_category`(TEXT) | FK 단일 | **중상** |
| 인쇄 캐시 | items의 print_method_id/media_id가 print_method_media와 중복 | 조회는 조인, 캐시 정리 | **중상** |
| pricing_method / item_group / code_prefix | 깔끔 | 유지 | 하 |

> audit 부수 발견: items는 `SELECT *` 없이 **컬럼명 30+개 하드코딩**. → 컬럼 *추가*는 안전(안 깨짐), *삭제*는 모든 SELECT 수정 필요 → **삭제는 맨 마지막에.**

## 3. 단계 (비파괴 → 게이트 → 파괴)

### Phase 0 — 기준 고정 (거의 완료)
- North-star 모델 문서화 ✅ / 영향도 audit ✅ / 정제 분류·역할·자재 모델 ✅(설계서 엑셀)

### Phase 1 — 분류축 정화 (비파괴, 되돌림 쉬움)
- 깨끗한 제품종류 카테고리 셋 확정(`품목분류_확정안.xlsx`) → `item_categories` 정리
- 기존 품목의 `category_id` 재배정 (인쇄방식/역할성 카테고리 → 제품종류로)
- 인쇄방식성 카테고리(솔벤/UV/전사)는 **삭제 않고 비활성**, 인쇄방식은 ②축으로
- **컬럼 삭제 없음.** 데이터 재배정만 → 문제 시 롤백 용이
- 검증: `npm run verify` + 품목/주문/재고 페이지 스모크

### Phase 2 — 단일 출처화 (비파괴, 앱 레이어)
- ~~역할: `item_type`을 진실의 출처로~~ **❌ 삭제 (2026-06-19, B-1 검증)** — prod 63/103이 다중역할(MATERIAL 53건이 판매겸업). `item_type`을 역할 정본으로 접고 플래그를 파생시키면 판매중 자재 53건 손실. **역할 정본 = dual 플래그(is_sales_item/is_purchase_item) 유지.** `item_type`은 분류 라벨로만. → [[design-item-role-multi-flag]]
- 카테고리: `category_id` 정본, `category` TEXT는 응답용 파생으로만 기록(쓰기 단일화)
- 소분류 동일
- **컬럼 삭제 없음**

### 🚦 결정 게이트 (Phase 2 직후)
- 질문: "이제 축이 정렬됐다고 느껴지나? 일상 등록/조회가 단순해졌나?"
  - **예 → Phase 3(정리)로**
  - **아니오 → (다) 전면 재설계로 escalate.** 이때 Phase 1·2 산출물(정제 분류·역할 단일화·audit·자재 모델)은 **새 설계의 입력으로 그대로 이월** → 헛수고 아님

### Phase 3 — 중복 컬럼 제거 (파괴적, 선택, 마지막)
- 읽기 경로가 전부 정본으로 옮겨진 뒤에만
- 후보: `category`/`sub_category` TEXT, ~~`is_sales/is_purchase`~~(❌ 제외 — 역할 정본, 다중역할 표현. B-1), items의 print 캐시
- 각 제거 전 동일 안티패턴 전수 grep(부분픽스 방지, CLAUDE.md 규칙)
- 마이그레이션 + 전체 `npm run build && npm run smoke`
