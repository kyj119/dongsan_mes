## 1. 현황

| 구분 | 상태 |
|---|---|
| 송장 **export** (엑셀 일괄 출력) | ✅ prod 완료 |
| 송장 **import** (운송장번호 일괄 입력) | ⏸️ 한진 반출 엑셀 양식 + 출고번호 보존 여부 확인 대기 |
| API 자동화 (발급·추적) | ⏸️ 솔루션 미선정 |
| 알림톡 한진 템플릿 | ⏸️ 미등록 (알림톡 go-live 패키지 D3와 연동) |

## 2. 결정 1 — 통합 솔루션 선택 (용준님)

로드맵 §2 분석 요지 (상세는 원문):

| 안 | 방식 | 적합성 |
|---|---|---|
| **가 (로드맵 권고)** | 통합 배송 솔루션 (스마트택배/굿스플로/위빅스) | 멀티 택배사(한진+대신) 한 번에, 계약 단순. 건당 100~300원 |
| 나 | 한진 직접 B2B API | 월 500건+ 물량이면 비용 유리, 계약 절차 김 |
| 다 | 웹 RPA | **권장 안 함** (회귀·약관 리스크) |

**결정에 필요한 입력**: ① 월 평균 한진 발송 건수(→ 가/나 분기점) ② 운임 정산 주체 ③ entity별 발신자 분리 여부(로드맵 §6-3).

## 3. 결정 2 — import 선행 확인 (솔루션과 무관하게 즉시 가능)

한진 측 반출 엑셀 1부만 확보되면:
1. 양식 컬럼 분석 → `shipments.tracking_number` 매핑 설계
2. **출고번호(또는 주문번호)가 왕복 보존되는지** 확인 — 보존되면 무키 매칭 불요, 안 되면 수신자명+연락처 퍼지 매칭(오매칭 리스크 검토)
3. import는 솔루션 계약 없이도 구현 가능 → **수동 운영 과도기 단축** (권고: 솔루션 결정과 분리해 선착수)

## 4. 착수 조건 정리

```
[용준님] 한진 반출 엑셀 1부 확보 ──→ import 구현 (1세션, 솔루션 무관)
[용준님] 월 발송량·정산 답변 ──→ 솔루션 계약 ──→ 로드맵 Phase A~C (3세션)
[솔루션 결정 후] 알림톡 한진 템플릿 등록 ──→ go-live 패키지 D3 매핑 갱신
```

## 5. 공수
import 단독: ~1세션. API 자동화: 로드맵 기준 3~4세션 (Phase A 인프라 → B 발급 → C 추적 폴링).
