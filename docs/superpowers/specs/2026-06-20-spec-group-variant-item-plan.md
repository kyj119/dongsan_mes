## 0. 모델 한 줄
**규격그룹(호수·판재두께·원단폭…) 정의 → 품목 + 그룹값 조합으로 변종품목 자동생성.** 변종품목 = 독립 일반품목(재고·단가·통계 per-variant). 그룹 = *생성·묶음·통계용 메타데이터*(인스턴스 비구속).

## 1. 적용 범위 (하이브리드 — 전부 변종 아님)
| 유형 | 처리 |
|---|---|
| 면적 출력물 (현수막·시트·판재출력 **제품**) | **단일 품목** + 면적단가(소재×인쇄방식×규격 기존컬럼) |
| 자재·grade 변종 (포맥스 두께·깃발 호수·원단 폭/코팅) | **규격그룹 → 변종품목**(재고/단가 정확) |

## 2. 스키마 (마이그 `0326`)
- `spec_groups`(id, name, unit, sort, is_active) — 규격그룹 마스터(사용자 관리)
- `spec_group_values`(id, group_id, **value_code**, label, sort, is_active) — value_code=ascii(5T,7HO), label=표시(5T,7호)
- `items` += `spec_group_id`(nullable), `spec_value`(nullable). **`item_group`(기존)** = 변종 base명으로 묶음.
- `items.ecount_code`(nullable) — ECOUNT 교차참조(레거시), item_code와 분리

## 3. ★ 품목 코드 체계 (재확인)

### 원칙
- **무의미 안정 base코드** + **변종값 suffix**. 
- **카테고리·인쇄방식 인코딩 금지**(옛 PM-1xxx=수성 식 = 재분류 시 코드 거짓말=축꼬임). 
- 단, **변종값(intrinsic·불변)** 은 suffix로 허용 — 5T 품목은 영원히 5T라 코드에 박아도 안전.

### 형식: `{타입}-{base순번4}[-{value_code}]`
| 요소 | 값 |
|---|---|
| 타입 | `P`(제품)·`G`(상품)·`M`(자재) — item_type |
| base순번 | 논리 base별 4자리(max+1). 포맥스=0019 |
| value_code | spec_group_values.value_code (변종만) |

### 예
- 현수막(단일) = `P-0001`
- 포맥스 두께 변종 = `M-0019-2T`·`M-0019-3T`·`M-0019-5T`·`M-0019-8T`·`M-0019-10T`
- 태극기 호수 변종 = `P-0033-1HO`·`P-0033-7HO`…
- base순번은 **변종끼리 공유**(M-0019-*) → 코드로 묶음 가시화

### 대안(단순): 변종도 순수 순번(M-0019,M-0020…). 가독성↓, 묶음은 item_group 의존. → **base+suffix 권장**(발주/주문 가독성)

## 4. 변종 생성 (멱등·비파괴)
- API/UI "변종 생성": base명+타입+카테고리+spec_group → 그룹 활성값마다 품목 생성
  (item_name=`{base} {label}`, item_group=base, spec_group_id, spec_value, code=base순번+value_code)
- **★안전 3규칙** (수정 우려 해소):
  1. 생성 = 빠진 조합만 추가(멱등). 기존 품목 **절대 안 덮음**
  2. 변종 = 생성 후 **독립 일반품목**(가격·이름·재고 자유 수정). 그룹은 메타데이터(비구속)
  3. 그룹 값 삭제/이름변경 = 기존 품목 무영향(스냅샷, 주문 FK 보존). 값 추가 = 신규만 생성

## 5. 품목 관리 (사용자 self-service)
- **규격그룹 관리 페이지**: 그룹·값 CRUD (용준님이 호수·두께·폭 등 추가/관리) + 권한(permission_pages)
- **품목 페이지**: item_group으로 변종 묶어 표시 + "변종 생성" 액션 + 개별 변종 자유 수정
- base는 템플릿(is_active=0, 비주문) 또는 그룹 헤더로 보존

## 6. 주문 입력
- 2단: **품목(포맥스) → 규격값(5T) → 변종품목 자동 resolve**. 또는 변종품목 직접 선택
- 면적 제품: 단일 선택 + 규격(W×H) 입력(기존)

## 7. 단가·통계
- 단가: 변종품목 `base_price` 각자. **호수=품목 base_price(GRADE표 0324 불요)** / 면적=㎡단가(별도 spec)
- 통계: `GROUP BY item_group / spec_group_id / spec_value / item` — 두께별·호수별·품목별 전부

## 9. 결정 현황
- **D1 코드 = ✅ A 확정**: `{타입}-{base순번4}[-{변종코드}]` (P-0001 / M-0019-5T / P-0033-7HO)

### D2 규격그룹 (확정 진행)
| 그룹 | 값 (value_code : label) | 적용 |
|---|---|---|
| **판재두께** | 1T·2T·3T·5T·8T·10T | 포맥스·폼보드·아크릴·자작나무 원판 |
| **호수** | 1HO~10HO=1~10호 + 특수 4HO1=4-1·7HO1=7-1·8HO1=8-1 *(전체 특수 목록 확인)* | 태극기·깃발·기류 |
| **원단폭** | 폭 mm *(목록 확인: 1100·1370·1520·1600?)* | 원단 자재(코팅 base × 폭) |

> value_code는 하이픈 없이(`4-1`→`4HO1`) → 품목코드 이중하이픈 회피(`P-0033-4HO1`).

### D2-원단 2D 해결 (지금 포함)
- **코팅종류 = 별도 base 품목**(1코팅원단·2코팅원단·메쉬원단·친환경원단·무코팅원단 *목록 확인*)
- **폭 = 원단폭 그룹** → 각 코팅 base × 폭 = 변종품목(재고 per 코팅×폭)
- 각 변종 → `items.parent_media_id`로 **소재(print_media, 9개 보존) 연결** → 제품 면적단가의 소재축 재사용

### D3 변종 대상
| 유형 | 변종? | 그룹 |
|---|---|---|
| 원자재 판재(포맥스·폼보드·아크릴·자작나무) | ✅ | 판재두께 |
| 깃발·기(태극기·깃발·기류) | ✅ | 호수 (→ 호수별 base_price, GRADE표 불요) |
| **원자재 원단(코팅별)** | ✅ | 원단폭 (코팅=base) |
| 현수막·출력물·시트·판재출력·배너(제품) | ❌ 단일 | 면적/FIXED 단가 |
| 부속품(GOODS)·간판 | ❌ 단일 | 멕기 1/2구·간판 견적 = 후순위 |

> ⚠️ 판재출력 **제품**이 소비하는 두께 자재(포맥스 5T 원판)는 BOM/자재연결로 후속.

### D4 ecount_code = ✅ 확정 (참조 컬럼)
- ECOUNT 출신 품목만 `items.ecount_code` 채움(참조용), 신규는 null. `item_code`와 분리. 업로드 시 원천에 옛 코드 있으면 매핑.
