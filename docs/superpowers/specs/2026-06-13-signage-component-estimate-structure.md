# 간판 구성요소 견적·작업지시 구조 — "조립 견적" 품목 모델 (MES 확장)

- **작성일**: 2026-06-13
- **상태**: 🟡 **방향 확정 (용준님) · 세부 enum/렌더 방식 보류** — 출력물 품목 정리·6개월 데이터 마이그레이션과 병행
- **배경**: 이카운트 ERP 입력 구조가 간판과 안 맞아 "통금액"으로만 올려왔음. 작업지시서는 `Z:\1. 광고물`에 AI 파일로 별도 작성. 이를 MES에 정식 도입해 **견적·작업지시·관리**를 한 구조로 묶는 것이 목표.
- **관련**: 출력물 품목 구조(`items` + `print_methods`/`print_media`/`finishing_methods`), `order_items.parent_item_id`(묶음), `bom_items`(MRP 자재 BOM), 웹 캔버스 워크벤치 spec(작업지시서 렌더 후보 인프라)

---

## 0. 핵심 결론

현재 MES 품목 구조는 **"출력 + 면적단가" 모델**(품목 + 인쇄방식 + 소재 + 후가공, ㎡ 과금)이다. 현수막·실사·전사 출력에는 맞지만, **간판은 가격이 면적이 아니라 "구성요소(부분품·작업) 라인의 합"에서 나오므로 맞지 않는다.**

→ 간판은 **별도 시스템을 새로 만들지 않고**, 기존 `items` + `order_items.parent_item_id` 위에서 **"구성요소 카탈로그를 가진 조립 견적 품목"으로 확장**한다. 즉 출력물의 인쇄방식/소재 분리와 동일한 발상이되, 분리 축이 **"구성요소"**다.

---

## 1. 간판 견적의 실제 구조 (작업지시서 4종 분석)

피자집(플렉스 프레임), 로뎀카페·농협 다수(채널 조명간판), 가로등 표지판(스텐) 샘플에서 공통 추출.

**간판 1건 = 부모(규격·조명여부·비고) + 구성요소 라인들의 합.** 각 구성요소는 *자기만의 가격 계산 규칙*을 가진다.

### 1.1 구성요소 카탈로그 (관찰 기준, 80~90% 커버 — "대충 맞음" 확인)

| 구성요소 | 계산 방식(calc_type) | 관찰 예시 | 옵션/메타 |
|---|---|---|---|
| 채널 | 규격기반 정액 (BY_SIZE) | 488,000 / 360,000 / 662,000 | 채널조립 여부 |
| 시트부착 | 정액 (FIXED) | 63,000 / 90,000 / 265,000 | 종류: LG조명시트·지정색펠·백색·HS1236 |
| LED조립 | 수량×단가 (PER_QTY) | 440ea×400, 646ea×400 | 브랜드(넘버원), 전선 굵기 |
| SMPS | 용량×개수 (BY_SPEC_QTY) | 300/400/500w × ea | 와트 선택 |
| 알루미늄바 | 규격(길이×폭)→금액 (BY_SIZE) | 7500×200=263,000, 8700×200=435,000 | 색상(연회색·백색·도색·HS1236도색) |
| 까치발 | 수량×단가 (PER_QTY, 기본 4,000) | 3~5ea×4,000 | 규격(150/200mm), 색상(청1·녹2·연회색·백색) |
| 조립배선 | 정액 (FIXED) | 130,000 | — |
| 등조립 | 정액 (FIXED) | 140,000 / 56,000 | — |
| 스텐카바 | 정액 (FIXED) | 450,000 / 620,000 | — |
| 조명용프레임 | 정액 (FIXED) | 260,000 / 175,000 | — |
| 발통 | 정액 (FIXED) | — | — |
| 입체 트림 글자 | 수량×단가 (PER_QTY) | 70,000, 62,000×4ea | 색상코드(LA9423NH·LB9534NH), 트림색 |

> ⚠️ 카탈로그는 "대충 맞음" 수준. 구현 착수 시 디자이너와 단골 구성요소 전수 확정 + 빠진 항목 보강.

### 1.2 계산 방식(calc_type) 4종 — 구조의 핵심

| calc_type | 의미 | 적용 구성요소 |
|---|---|---|
| `FIXED` | 정액 입력 | 시트부착·조립배선·등조립·스텐카바·프레임·발통 |
| `PER_QTY` | 수량 × 단가 | LED조립·까치발·입체글자 |
| `BY_SIZE` | 규격(가로×세로/길이) → 금액 (수동 또는 규격단가) | 채널·알루미늄바 |
| `BY_SPEC_QTY` | 사양(와트 등) 선택 × 개수 | SMPS |

### 1.3 간판 하위유형 (sub_type)

| 유형 | 가격 구조 | 비고 |
|---|---|---|
| ① 채널·조명 간판 | **구성요소 분해형** (위 카탈로그) | 가장 복잡·핵심. LED/SMPS/채널/알루미늄바 |
| ② 표지판·스텐류 | **개당 단가 × 수량** | 예: 스텐 600×150 × 15개. 구성요소 분해 없음 |
| ③ 플렉스 프레임 | 구성요소 분해형 (프레임·카바·등조립·까치발) | 피자집 샘플 |

## 2. 데이터 구조 (초안 — 착수 시 확정)

### 2.1 설계 원칙
- **새 병렬 시스템 금지.** `items`/`order_items` 위에서 확장 → 주문·재고·정산 단일 흐름 유지.
- 간판 1건은 `order_items`의 **부모 라인 + 자식(구성요소) 라인**으로 표현. `parent_item_id`(기존) 재사용.

### 2.2 구성요소 마스터 (신규)
```sql
CREATE TABLE IF NOT EXISTS sign_components (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,                 -- 채널, LED조립, 까치발 ...
  calc_type TEXT NOT NULL             -- FIXED | PER_QTY | BY_SIZE | BY_SPEC_QTY
    CHECK(calc_type IN ('FIXED','PER_QTY','BY_SIZE','BY_SPEC_QTY')),
  default_unit_price REAL DEFAULT 0,  -- 기본 단가 (까치발 4000 등)
  options_json TEXT,                  -- 색상/사양 선택지 (색상코드, 와트 등)
  sort_order INTEGER DEFAULT 0,
  is_active INTEGER DEFAULT 1,
  entity_id INTEGER NOT NULL DEFAULT 1
);
```

### 2.3 간판 주문 표현
- 부모 라인: `order_items` (item_type='SIGN'), 규격(width/height), 조명여부·채널조립여부·sub_type은 `specification` 또는 신규 컬럼/`sign_meta_json`.
- 자식 라인: `order_items` (parent_item_id=부모, `sign_component_id` 참조, qty/unit_price/계산결과 amount).
- 부모 amount = 자식 합 (기존 묶음 청구 패턴과 동일).

### 2.4 단가방식 확장
- `items.pricing_method`에 값 추가 검토: 현행 `FIXED`/`AREA` → **`COMPONENT`(조립 견적)** 추가. 간판 부모 품목은 COMPONENT.

## 3. BOM이 두 종류 — 절대 섞지 말 것

| 구분 | 견적 BOM (구성요소) | 자재 BOM (원자재) |
|---|---|---|
| 내용 | 채널·카바·LED조립·까치발 | 아크릴 N장, LED N개, SMPS N개, 알루미늄 길이 |
| 역할 | **가격을 만들고 작업지시서가 됨** | 재고 차감·MRP(자재계획) |
| 테이블 | `sign_components` + 자식 라인 (신규) | `bom_items`(기존, `usage_per_sqm`) |
| 시점 | **1차 (지금)** | 2차 (나중) |
| 출력물과의 관계 | 출력물엔 없음(가격=면적) | 출력물·간판 공통 후방 레이어 |

- 용준님 "BOM을 간판·출력물 양쪽에" = 실제로는 **자재 BOM(2번)**을 공통으로 쓰겠다는 것. 단 `bom_items`는 현재 `usage_per_sqm`(㎡비례)만 → **개수 단위(per-unit) 소요 지원 확장** 필요(간판 부품은 개수).
- **1차 범위는 견적 BOM만.** 작업지시서는 견적 BOM만으로 생성됨.

## 4. 작업지시서 자동 생성

샘플 레이아웃 = **디자인 이미지 + 좌측 제작지시(LED조립 넘버원/전선 굵은거/조도향상필름/종이도안) + 우측 구성요소·금액 + 규격·배송일**. 구조화 입력 시 이 한 장이 그대로 출력 → **별도 작업이 아니라 구조의 부산물.**

- 렌더 방식(보류): ①HTML/PDF 템플릿 ②웹 캔버스 워크벤치 인프라 재사용(디자인 이미지 합성). 워크벤치 P2 진척에 맞춰 결정.
- 제작지시 텍스트(전선 굵기·조도향상필름·채널조립없음 등)는 구성요소 옵션/비고에서 끌어옴.

## 5. 6개월 데이터 마이그레이션에 미치는 영향

| 품목군 | 과거 데이터 상태 | 마이그레이션 |
|---|---|---|
| 출력물(현수막·전사 등) | 라인별 풀데이터 보유 (6개월) | 품목+인쇄방식+후가공 파싱 후 정식 이관 |
| **간판** | **이카운트에 "통금액"만** — 구성요소 분해 없음 | **과거분은 구성요소 복원 불가.** 부모 라인(통액)만 이관, **구성요소 구조는 신규 입력분부터** 채움 |

→ 간판은 "지금부터 제대로", 출력물은 "과거까지 소급"으로 경로가 갈린다.

## 6. 확정 / 잔여

**확정 (2026-06-13 용준님)**
- 간판 = 단일 품목 안 나눔, 인쇄방식·후가공·옵션 분리 (출력물과 동일 철학)
- 간판은 별도 시스템 X → `items`/`order_items` 확장
- 간판 시공은 가끔 → 시공 전용 구조 불필요(주문 항목/옵션으로 처리)
- 구성요소 표준화 가능 확인 (카탈로그 ~12종, "대충 맞음")
- BOM 양쪽 활용 의향 → 자재 BOM(2차)으로 정리, 견적 BOM은 신규 구조

**잔여 (착수 시 확정)**
1. 구성요소 카탈로그 전수 확정 + calc_type 매핑 (디자이너 협의)
2. `BY_SIZE` 가격: 수동 입력 vs 규격단가표 자동 — 채널·알루미늄바
3. sub_type ②표지판(개당형) 별도 처리 범위
4. 작업지시서 렌더 방식 (HTML/PDF vs 캔버스)
5. `pricing_method='COMPONENT'` 추가 vs `sign_meta_json` 방식 택일
6. 자재 BOM(`bom_items`) per-unit 확장 시점(2차)
