  - ⚠️ 내보내기 컬럼이 **리스트 화면 표시 컬럼을 그대로 따른다** → 이번 건은 9열(거래처코드·거래처명·대표자명·전화·모바일·검색창내용·최초작성일자·사용구분·이체정보)로 **업태·종목·주소·Email·Fax가 빠졌다**. 보유 `ESA001M (1).xlsx`(2026-04-04·2,674건)엔 13열로 있다.
  - 신규 거래처 등록 시 부가정보가 필요하면 리스트 표시 컬럼을 늘려 재내보내기(`Option`은 이번 세션에서 무반응 — 재시도 필요). **매칭 자체는 거래처코드+거래처명으로 충분하므로 이관 블로커 아님.**
  - `Excel ▾`의 `Excel(이체정보)`는 계좌정보라 사용하지 않음.
- **다운로드 파일명 패턴이 리포트별로 다르다**: 판매현황 = 15자 대문자(`50FGYFSSCE3DXY1`), 수금현황·채권 = 16자 혼합(`mtk0whEJP4JP7Ros`), 거래처등록 = `ESA001M (N)`. 감시 스크립트의 정규식을 하나로 고정하면 놓친다.

## 5. 리스크 · 함정 (선명 이관에서 실제로 터진 것)

1. **소계행 함정**: 채권/채무 파일에 "합계"·"/계"·"00001/김용준 계" 소계행이 섞임 → 단순 SUM 하면 3배 착시. **"합계"행이 정본**.
2. **로컬 검증 false pass**: 검증용 sqlite에 실 CHECK/UNIQUE 제약을 복제하지 않으면 통과했다가 prod에서 무음 드롭(선명 245건). **실 DDL 복사 + `PRAGMA foreign_keys` 강제**.
3. **CHECK 제약**: `bank_transactions.match_status` ∈ UNMATCHED/SUGGESTED/CONFIRMED/APPLIED/IGNORED (**MATCHED 무효**). `items.item_type` ∈ PRODUCT/GOODS/MATERIAL (**SERVICE 없음** → 운반비·할인 등은 GOODS + deduction_method=NONE).
4. **금융 write는 2단계**: 분류표 CSV 제출 → 용준님 승인 → SQL 반영(+롤백 SQL 동봉). payments·purchase_payments·미수/미지급 변동은 임의 진행 금지.
5. **품목 매칭 6,770 라벨**: 선명은 999라인 98.8%까지 갔지만 수작업 단계가 컸다. 동산은 7배 → **금액 기준 커버리지 목표를 먼저 합의**하고, 미매칭은 `item_id NULL + 원문명` 보존(금액엔 영향 없음).
6. **인코딩**: `wrangler d1 --json`을 python 파이프로 받으면 Windows 콘솔이 한글을 surrogate로 파손 → **파일 리다이렉트 후 utf-8 로드**.
7. **법인간거래**: 내부 3사(동산기획·선명·청주) 상호거래는 원장/미수에서 제외되고 회계허브가 흡수. 이카운트 판매현황의 내부거래 라인은 기존 `ICM-*` 7건과 중복.

## 6. 실행 단계

- **Phase 0 (지금)** — 내보내기 확보. 위 1~5번(6·7은 선택). 파일은 `품목마스터/원천주문데이터/` 에 `동산_판매현황_2601~2603.xlsx` 식으로.

- **Phase 2** — 매출: 주문/라인 적재 + `order_billing_groups(BILLED)` + `orders.billing_status` 미러. 품목 매칭은 금액 상위부터 단계적.

- **Phase 5 (반복 동기화)** — 이카운트 Open API. 인증키는 `wrangler secret`. 증분 키는 `일자-No.` 기반 멱등 UPSERT(선명 `content_key` + `INSERT OR IGNORE` 패턴 준용).

1. **기존 품목 우선 매칭** — prod 활성 품목에 최대한 붙인다(품목코드가 있으면 코드 기준, 없으면 품목명+규격 정규화).
