# 정기지출 누락 탐지 — MES 통장 ↔ SmartA 판관비 (2026-08-05)

**계기**: MES 고정비가 동산기획 7건 월 3,631,280 뿐인데 **임차료·통신비가 아예 없었다**.
**결과**: 월 15,872,480(연 1.90억) 누락 확인 → 11행 등록. 고정비 **7건 → 18건 · 월 19,503,760**.

## 탐지 방법 — 통장이 먼저, 세무장부가 확인

세무장부 판관비를 훑는 것보다 **MES `bank_transactions` 의 반복 출금**이 빠르다(실제 현금흐름이라 바로 고정비 후보가 된다).

```sql
SELECT counterpart_name, COUNT(DISTINCT substr(transaction_date,1,6)) AS months,
       COUNT(*) n, ROUND(AVG(amount)) avg_amt, MIN(amount) mn, MAX(amount) mx
FROM bank_transactions
WHERE transaction_type='WITHDRAWAL' AND entity_id=1 AND transaction_date>='20260101'
GROUP BY counterpart_name HAVING months>=5 AND avg_amt>=30000 ORDER BY avg_amt DESC;
```

그다음 **세무장부에서 계정을 확인해 성격을 확정**한다(합계잔액시산표로 비용 계정 규모 → 거래처원장으로 거래처별 금액).
계정을 못 찾은 건은 등록하지 않는다 — 저축·자산이 비용으로 섞이는 걸 막는 유일한 방법이다.

## ★ 자동탐지가 놓치는 함정 — 거래처명 파편화

같은 상대인데 통장 표기가 갈려 반복 탐지에서 빠진다.

| 실제 | 통장 표기 |
|---|---|
| 성낙선 임차료 | `타행농협> 성낙선` · `타행농협&gt; 성낙선` · `홈) 농협성낙선` |
| 하나생명 보험료 | `하나생01013` → `하나생02014` → `하나생03015` … **매월 바뀜** |

`&gt;` 는 **HTML 이스케이프가 그대로 저장**된 것이다. 하나생명은 회차번호가 상대명에 붙어 8건이 전부 별개로 잡힌다.

**해결 (2026-08-05)** — `src/utils/counterpart.ts`
- 두 적재 경로(수동 import · 바로빌 sync)에서 **HTML 엔티티 복원**, 기존 19행 백필. 이스케이프 잔량 0.
- `counterpartKey()` = 채널 표식(`홈)`·`홈>`·`타행농협>`·`CMS`) 제거 + **채널이 확인된 경우에만** 경유 은행명 제거.
  채널 없이 은행명을 떼면 `하나로마트` 가 `로마트` 가 되므로 조건을 건다.
  **숫자 접미사는 안 뗀다** — `지로LGU+57011972` 와 `지로LGU+24081972` 는 서로 다른 회선이다.
- `GET /api/bank/recurring-candidates` 가 이 키로 묶고 **이미 고정비·차입금으로 추적 중인 상대는 제외**한다.
- 실측 검증: 전체 1,998종에 적용 → **24개 그룹 병합, 전부 정확, 과병합 0**(1글자 키·빈 키 없음).

⚠️ **자동매칭에는 쓰지 않는다.** `bank_match_rules` 는 재현율보다 정밀도가 원칙이라 키를 넓히면
서로 다른 상대가 한 규칙에 걸린다. 이 키는 **탐지·그룹핑 전용**이다.

⚠️ 남은 한계: **하나생명 회차형**(`하나생01013`→`하나생02014`)은 이 키로도 갈린다.
증가하는 회차번호와 고유 식별번호를 규칙으로 구분할 방법이 없어 손대지 않았다.
차입금 계좌번호형 상대명(`60298020082142-00001`)도 채권자명과 매칭되지 않아 후보에 남는다.

## ★ 부문별 손익 고정비 안분 결함 (같이 수정)

적재 직후 `/hr` 공통비 풀이 2026-01~08 기준 **238,190,400** 으로 나왔다.

```
-- 종전 (departments.ts)
SELECT SUM(amount) FROM fixed_expenses
 WHERE frequency='MONTHLY' AND start_date <= :to AND (end_date IS NULL OR end_date >= :from)
fixedCommon = SUM * months        -- ← 전 기간 개월수를 곱한다
```

WHERE 는 **기간이 하루라도 겹치면 통과**시키는데 합계엔 전 기간 개월수를 곱했다.
→ **8월에 시작한 고정비가 1~7월에도 계상**된다. 월별 중첩만 더하도록 수정.

검증 (배포 후 실측):

| 조회 | fixed_common | |
|---|---:|---|
| 2026-01~08 | 57,916,740 | 238,190,400 에서 교정 |
| 2026-08 | 19,503,760 | 현재 월 총액 |
| 2026-06 | 6,201,320 | **적재 전 월 총액 그대로** — 과거가 오염되지 않음 |
