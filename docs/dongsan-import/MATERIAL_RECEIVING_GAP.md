# 자재 입고 관리 진단 + 통장 근거 매입 갭 (2026-08-06)

회계(금액) 정합이 끝난 뒤 "자재 입고는 어디까지 됐나"를 점검한 결과다.
**결론: 금액 축은 거의 끝났고, 입고(수량·재고) 축은 시작도 안 했다.**

## 1. 입고 관리 = 미가동

| 항목 | 값 |
|---|---|
| `inventory_receipts` / `inventory_receipt_items` | **0 / 0** |
| `inventory_transactions` | **1건** |
| `inventory_fifo_layers` / `inventory_auto_deductions` / `pp_material_deductions` | **0 / 0 / 0** |
| `inventory` (동산기획) | 74행 · **수량≠0 은 1품목** |
| 원자재 마스터 (활성) | 787품목 |
| 2026 매입 이력 있는 품목 | 391품목 |

모듈은 완성돼 있다 — `src/routes/inventory.ts:319~` 가 입고 전표 → `inventory` upsert →
`inventory_transactions` 기록 → 검수까지 처리한다. **미구현이 아니라 미사용이다.**

### ⚠️ 착시 하나 — "입고 100% 완료"로 보인다

`purchase_order_items.received_quantity` 가 **전 라인 `= quantity`** 로 채워져 있고
`purchase_orders` 503건이 **전부 `RECEIVED`** 다. 이관이 만든 값이다.

실제 입고를 시작하면 **미입고 잔량이 0으로 계산돼 입고 대상이 아예 안 뜬다.**
입고 운영을 켜기 전에 `received_quantity` 를 0으로 되돌리는 결정이 선행돼야 한다
(되돌리면 반대로 "전량 미입고"가 되므로, 어느 시점부터 실입고를 잡을지 기준일이 필요하다).

### 매입 명세 축은 살아 있다

동산기획 2026 라인 1,079건 중 품목 미연결 53건(**95% 연결**), 수량 누락 0건.
"무엇을 얼마나 샀는지"는 있고 "창고에 들어왔다"는 기록만 없는 상태다.

## 3. ★ AP 대사가 맞았는데 왜 매입이 빠져 있었나

**잔액만 맞췄기 때문이다.** 세무장부 251 은 세금계산서 기준 채권채무 **잔액**이라,
기초잔액 + 당기 일부만 넣어도 잔액은 일치한다. 그래서:

- **오다플래그처럼 즉시 결제해 251 잔액이 0인 매입처는 대사 그물에 아예 안 걸린다** (통장 1.29억)
- 진안알미늄은 잔액 6,554,200 이 정확한데 통장은 4,000만이 나갔다 — 매입도 지급도 나머지가 통째로 없었다

즉 **「AP 대사 완결」= 채무 잔액 정확**이지, **매입 거래 전수 적재는 아니다.**
앞선 `SMARTA_AP_RECONCILE.md` 의 완결 선언은 이 범위로 읽어야 한다.

### ★ AP 불변 설계

매입 PO 와 지급을 **동액·동일자**로 넣었다. `AP = PO − 지급 − 조정` 이므로 순증 0 →
세무장부 대사가 깨지지 않는다. 적재 목적은 잔액 교정이 아니라 **거래 이력·거래처 지출 가시성**이다.

### 한계 — 이 적재가 못 하는 것

- **품목 라인이 없다.** 통장은 금액만 알려준다. 자재 소진·재고와 연결되지 않는다
- **매입일이 지급일로 대체됐다.** 오다플래그처럼 전월 마감분을 결제하는 곳은 인식 시점이 뒤로 밀린다
- 신규 2곳(대진국기사·극동잔넬)은 **사업자번호 미확보** → `client_code` 가 `PENDING-*` 다.
  세금계산서에서 번호를 확보하면 `client_code`·`business_registration_number` 를 UPDATE 할 것
- **제외**: 우드케이 4,535,850 · 대진국기사 택배운임 1,650 = 운반비 성격이라 매입이 아니다
- **미반영 입금**: 오다플래그 05-11 2,050,000 · 대진국기사 04-30 66,000 (반품/상계 추정, 근거 미확보)
