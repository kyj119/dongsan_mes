# 목록 화면 UX 갭 감사 — 이카운트 대비 (2026-08-08)

> 트리거: "주문관리 페이지 전체 주문 수량이 어떻게 산정되는지 모르겠다. 필터·기본값도 아쉽다."
> 범위: 코드 수정 없음. 주요 거래 목록 13개 페이지를 동일 항목으로 전수 대조.
> 산출: 갭 목록(G1~G12) + 우선순위 + 페이지별 현황 매트릭스 + 실행 순서.

## 0. 결론 3줄

1. **상단 통계 카드와 아래 목록은 서로 다른 모집단을 센다.** 통계는 전 기간·취소 포함·필터 무시, 목록은 최근 1개월·취소 제외·필터 반영. 두 숫자는 구조적으로 일치할 수 없다. 같은 결함이 주문·발주·견적·출고·구매요청 5개 페이지에 동일 패턴으로 존재한다.
2. **수량·금액 합계가 어디에도 없다.** 주문 목록에는 수량 열 자체가 없고(`item_count`는 품목 *건수*), 합계행이 있는 곳은 원장·견적 상세뿐이다. 이카운트 목록의 기본 합계행(수량·공급가·부가세·합계) 대응물이 없다.
3. **필터 상태를 기억하는 페이지는 주문 1곳뿐**이다. 나머지 12개는 페이지를 떠나면 조건이 초기화된다. 반대로 주문은 페이지 번호까지 복원하면서 그 사실을 화면에 알리지 않는다.

## 2. 갭 목록

### P0 — 숫자를 믿을 수 없음 (오판 유발)

#### G1. 통계 카드 모집단 ≠ 목록 모집단
`/api/orders/stats`(`src/routes/orders/queries.ts:86`)는 `orders` 전량을 `GROUP BY status`로 세고, `total`에 모든 상태를 합산한다(`:100`). 즉:

- **기간 조건이 없다** — 이관분 포함 전 기간 누적
- **`CANCELLED`·`QUOTATION`도 `total`에 포함** — 목록은 기본으로 이 둘을 제외한다(`src/scripts/orders.js:402`)
- **검색어·거래처·배송방법·회계상태·우선순위·지연 필터를 전부 무시**

반면 목록은 기본 최근 1개월(`src/scripts/orders.js:321`)에 위 필터가 모두 걸린다. 화면 상단 "전체 주문 N"과 하단 "총 M건"이 크게 어긋나는 것이 정상 동작인 상태다.

동일 패턴 확산:

| 페이지 | stats 엔드포인트 | 반영하는 조건 | 무시하는 조건 |
|---|---|---|---|
| 주문 | `orders/queries.ts:86` | 법인 가시성만 | 기간·검색·상태 외 전부 |
| 발주 | `purchaseOrders/po-queries.ts:22` | 법인·법인간거래 토글 | 기간·검색·공급처 |
| 견적 | `quotations.ts:154` | 검색·거래처 | **기간** |
| 출고 | `shipments.ts:109` | 법인·취소제외 | 기간·검색 |
| 구매요청 | `purchaseRequests.ts:152` | 일부 조건 | 기간 |

견적만 검색을 반영하고, 기간을 반영하는 곳은 하나도 없다.

#### G2. 수량·금액 합계 부재
- 주문 목록 SELECT에 수량 집계가 없다(`src/routes/orders/core.ts:33-51`). `item_count`는 품목 **건수**이며 수량이 아니다.
- 테이블 헤더에도 수량 열이 없다(`src/pages/orders.ts:183-194`: 주문번호·거래처·품목·납기일·금액·상태·회계반영·등록일·액션).
- 조회 결과의 **금액 총합도 없다**. 페이지네이션 옆 "총 N건"(`src/scripts/orders.js:288,309`)이 유일한 집계다.
- 합계행(`tfoot`)이 있는 곳: 원장·급여·리포트·견적서/명세서 **출력물**뿐. 목록 화면에는 없다.

이카운트는 조회 즉시 하단 합계로 "이 조건의 총 수량·공급가·부가세·합계"를 보여준다. 현재는 CSV로 내려 엑셀에서 더해야 같은 답을 얻는다.

#### G3. 기본 기간 필터가 숨어 있음
기본 `date_from = 오늘-1개월`이 자동 적용되는데(`src/scripts/orders.js:321,1521`), 해당 입력은 "더보기" 접힌 패널 안에 있다(`src/pages/orders.ts:126-135`). 접힌 상태에서는 **왜 지난달 주문이 안 보이는지 화면에서 알 수 없다.** 활성 필터를 요약해 보여주는 칩이 없다(전 페이지 중 `materialForecast`·`shipments`에만 유사 UI 존재).

#### G5. 통계 카드에 드릴다운 없음
카드 4개는 표시 전용이다. "확정 12"를 눌러 확정 목록으로 가는 동작이 없어, 사용자가 상태 셀렉트를 다시 찾아 골라야 한다.

#### G6. 정렬 기본값·선택지 부족
- 기본 `created_at_desc`(`src/pages/orders.ts:119`). 이관 데이터는 `created_at`이 "이관 실행 시각"이라 업무상 무의미 — CLAUDE.md 정렬 규칙(업무일자 우선)과 충돌한다.
- 선택지가 등록일·납기일 4종뿐. **금액순·거래처명순이 없다.**

#### G7. 초기화 버튼 편차
`resetAllFilters` 계열이 있는 페이지는 주문·거래처 2곳뿐. 나머지는 조건을 하나씩 손으로 되돌려야 한다.

## 5. P1-1 · P1-2 구현 기록 (2026-08-08, 미배포)

### P1-2 — 활성 조회조건 칩 (D2)

P1-1이 만든 "집계 기준" 캡션과 칩이 **같은 조건을 두 번 말하게 되므로, 캡션 줄을 칩 행으로 승격**시켰다(정보 중복 제거). 조건 표기가 화면에 한 곳만 존재한다.

- 기본 최근 1개월도 사용자가 고른 조건과 **똑같이 칩으로** 뜬다 — "왜 지난달이 안 보이지"가 화면에서 해소된다(G3).
- 칩의 `✕` = **그 조건만** 해제(나머지 유지). 기존 「초기화」 버튼은 기본값 복귀라 역할이 다르다.
- 조건이 없으면 `전체 기간`·`취소·견적 제외`를 **회색 비활성 칩**으로 표기 — 빈 줄이 되지 않게 하고 암묵 규칙을 드러낸다.
- 카드에 없는 상태(취소 등) 선택 시 **경고 칩**("위 카드는 이 상태를 포함하지 않음")으로 카드-목록 불일치를 숨기지 않고 드러낸다.
- 칩·카드 강조는 필터 값만으로 그린다 — `loadOrders()`에서 렌더하므로 **통계 API가 실패해도 조건 표시는 남는다**.
- 상태 라벨은 셀렉트 옵션 텍스트를 정본으로 읽는다(`ordStatusFilterLabel`). 라벨을 따로 적으면 두 벌이 된다.

⚠️ 작업 중 `check:dom` 훅이 페이지에서 제거한 `#orderStatsCaption`의 잔존 참조를 잡아냈다(5→6건). 훅이 의도대로 작동한 사례.

### P1-1 — 통계 카드 필터 연동·드릴다운 (D1)

**조치의 핵심은 카드 수정이 아니라 조회조건 SSOT 신설이다.** 카드만 고치면 다음 조건 추가 때 또 갈라진다.

| 파일 | 변경 |
|---|---|
| `src/routes/orders/listFilter.ts` | **신설.** `buildOrderListFilter(c, {skipStatus})` — 가시성·상태·검색·기간·제외상태·우선순위·금액·배송·회계·지연 전 조건을 한 곳에서 조립 |
| `src/routes/orders/core.ts` | 목록·카운트 WHERE 2벌(약 145줄)을 빌더 호출로 대체 |
| `src/routes/orders/queries.ts` | `/stats` 를 빌더 기반으로 교체(`skipStatus`), CSV export도 빌더 공유 |
| `src/pages/orders.ts` | 카드 4개를 `<button>` 으로 전환(드릴다운·강조), 기준 캡션 영역 추가 |
| `src/scripts/orders.js` | `ordReadFilters`/`ordBuildParams` 클라 SSOT, `loadOrderStats` 필터 연동, 칩·강조·드릴다운 토글(`ordRenderFilterChips`·`ordClearFilter`) |

곁가지로 드러난 실결함 2건 — 조건이 흩어져 있어 생긴 것이라 통합과 동시에 해소됐다:

1. **CSV export에 주문 가시성(법인) 필터가 없었다.** 타 법인 주문이 함께 내려갔다.
2. **카운트 쿼리의 금액 범위에 NaN 가드가 없었다.** 목록(가드 있음)과 총건수가 갈릴 수 있었다.

설계상 결정:

- 카드는 **status를 제외**하고 집계한다(`skipStatus`). 카드가 곧 상태 선택 수단이므로 자기 자신으로 걸러지면 드릴다운이 불가능해진다. 따라서 카드 = 현재 스코프의 상태별 분포, 전체 = 그 합.
- `status` 파라미터에 **복수 값(콤마)** 을 허용했다 — 「생산중」= `PRINTING,PRINT_DONE`.
- 카드에 없는 상태(취소 등)를 고르면 캡션이 "목록은 선택한 상태만 표시 — 카드와 다름"을 명시한다.

검증: tsc·build·`node --check`·smoke 110/110·`audit:entity` 누락 0·`sort-audit` P1 0건·`check:dom` 기준선 5건 유지.
로컬 실브라우저 — P1-1: 9개 필터 조합과 드릴다운 3종 전량 카드==목록 일치, 토글·강조 정상.
