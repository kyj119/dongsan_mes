# 2026-09-18 성능 전수 감사 — 페이지 병목·기능 속도

**결론: 느린 게 아니라 컸다.** 페이지 전환·API 응답시간은 이미 건강했고(SPA 62~102ms · API 중앙값 ~60ms · 500 0건),
실제 낭비는 ①화면이 쓰지도 않는 페이로드 ②클릭이 어느 내비게이션 경로를 타는가 ③상관 서브쿼리의 잠재 위험이었다.

세 가지 다 **기존 게이트가 원리상 못 잡는다** — 357KB 응답도 200이고, 전체 내비게이션도 정상 동작이며, 상관 서브쿼리도 지금은 빠르다.
`typecheck`·`build`·`smoke`·`journey` 전부 초록이었다. (§조용한 격하·§계산 규칙과 같은 형태다.)

## 1. 실측 기준선 (prod, 2026-09-18)

| 축 | 실측 | 판정 |
|---|---|---|
| SPA 전환(사이드바=주 동선) | 첫 API 27~38ms · 데이터 표시 **62~102ms** | 양호 |
| 전체 내비게이션(캐시 있음) | 123~172ms · 데이터 표시 165~279ms | 양호 |
| 전체 내비게이션(**최초 방문**) | **1,064ms** (Tailwind Play CDN 725ms) | §4 참조 |
| GET 430건 전수 | 200 응답 309건 · 최악 735ms · 평균 27.8KB | 양호(500 **0건**) |
| 페이지 HTML | full 65~156KB(br) · SPA 4~98KB | SPA가 64% 절감 중 |
| D1 통계 | `sqlite_stat1` 508행 | 정상(ANALYZE 돌고 있다) |

| 같은 페이지 중복 요청 | 0건 | 양호 |

측정 방법: 라우트 맵(`app.route` + 각 라우터의 `.get`)에서 무파라미터 GET 654개를 뽑아
부작용 의심 경로(발송·수집·동기화·생성) 12개를 뺀 430개를 2회씩 호출해 빠른 쪽을 채택.
페이지는 Playwright로 33개를 실제로 열어 XHR 타임라인·직렬 체인 깊이·중복·콘솔 오류를 기록.

⚠️ **측정 아티팩트 주의** — 중간에 「SPA가 전체 내비게이션보다 2~3배 느리다」는 결과가 나왔는데,
Playwright `page.click()` 의 actionability 대기가 섞인 것이었다. JS 직접 클릭(`el.click()`)으로 재측정하니 정반대다.
전환 성능을 잴 때는 **클릭 대기를 배제**하고, 판정 기준을 「데이터가 화면에 보일 때까지」로 통일한다.

## 2. 고친 것

| # | 문제 | 근거 | 조치 |
|---|---|---|---|
| A1 | **로스율 숫자 하나 때문에 실사 상세 357KB** 를 받아 브라우저에서 합산 | `inventory.js:67` · 페이지 XHR 총량의 95% | 목록이 합계를 싣는다(`with_loss=1`) → **요청도 1개 사라짐** |
| A2 | 공급처 필터가 활성 거래처 **전량 2,890곳 218KB** | `purchaseOrders.js:85` · 실제 선택 가능한 건 **123곳** | `has_po=1`(발주 이력 있는 곳만) |
| B | 설정·프리셋이 **모든 목록 화면에서 직렬 2왕복** | `shell.js` `load()` → `loadPresets()` | `?presets=<pageKey>` 로 한 응답. **순서 보장은 그대로** |
| C1 | **`pushState` 가 페이지 스크립트 실행 뒤**라 스크립트가 이전 주소를 읽음 | 사이드바 링크엔 쿼리가 없어 드러나지 않았다 | 스크립트 삽입 **전**으로 이동 |
| C2 | `location.href` 49곳·본문 링크가 SPA를 비껴감 | 62~102ms ↔ 165~279ms | `navigateTo()` 21곳 교체 + 본문 링크 인터셉트 |
| D | 상관 서브쿼리 최악 **2.7M·1.9M 행** | `purchaseCandidates.ts:87` · `items.ts:515` | GROUP BY 선집계 + LEFT JOIN |

**C2 의 안전장치** — `navigateTo()` 는 세 경우에 전체 내비게이션으로 폴백한다:
①외부/비내부 주소 ②**같은 pathname 재진입**(페이지 스크립트가 두 번 돌면 `?raw` 전역 스코프에서 재선언 충돌 —
게다가 같은 화면이라 SPA 이득도 없다) ③**해시가 붙은 주소**(`pushState` 는 `hashchange` 를 발화시키지 않아
hash 로 탭을 여는 6개 페이지가 기본 탭에 머문다 — #622 와 같은 축).
로그인·권한 리다이렉트(`/login`·`/no-permission`·`/`)와 단독 레이아웃(portal·purchaseInvoice)은 **의도적으로 그대로 둔다**.

## 3. 고치지 않은 것 — 이유가 있다

- **`bank.ts:83` 등 계좌 신선도 상관 서브쿼리**: 바깥 행 수가 구조적으로 작다(계좌 17개).
  선집계로 바꾸면 거래 6천 행을 전부 접게 되어 **오히려 손해**다. 거래처(3천)·품목(1천) 축과 다르다.
- **`/api/settings/entity` 124KB**: 도장·로고 base64 — **화면이 실제로 쓴다**(미리보기·저장 폼). 정당한 페이로드.
- **`/api/prices/price-overview` 261KB · `/api/attendance/month` 152KB**: 그 화면의 본 데이터. 페이징은 UI 변경을 수반한다.
- **1MB 응답 2건**(`/tax-invoices/eligible-orders` 1.28MB · `/ai-analysis/batch-results` 1.08MB): 저빈도 화면이라 후순위.

## 4. Tailwind Play CDN — 전환 보류(판단 대기)

`cdn.tailwindcss.com` 은 **브라우저에서 CSS 를 런타임 생성**하는 개발용 빌드다(공식 문서상 프로덕션 비권장).
차단 실험에서 최초 방문 load 가 **1,064ms → 287ms** 였다.

**그런데 이득이 최초 방문 1회뿐이다** — 캐시된 재방문에서는 차단해도 162ms ↔ 163ms 로 **차이가 없다**.
반면 비용이 크다:

- **동적 클래스가 실재한다** — `iaBatchTest.js:229` `grid-cols-${Math.min(groups.length,4)}`.
  Play CDN 은 런타임 생성이라 지금 동작하지만, 빌드 CSS 로 바꾸면 **조용히 깨진다**(safelist 를 영구 관리해야 한다).
- 폭발반경이 **전 화면 스타일**이다. 88페이지 시각 검증이 필요하다.
- `dist/` 는 `_worker.js`·`_routes.json` 뿐이고 `_routes.json` 이 `/*` 전체를 worker 로 보낸다 —
  정적 자산 서빙을 안 쓰므로 CSS 를 라우트로 서빙하는 배선이 따로 필요하다(가능하지만 추가 작업).
- `node_modules` 는 worktree 간 junction 공유라 devDependency 추가가 다른 세션에 영향을 준다.

시험 생성은 해 봤다(`npx tailwindcss@3`, content=`src/**/*.{ts,tsx,js}`) → **60KB minified**(brotli 약 10KB), 생성 자체는 정상.
⚠️ 이때 「CDN 대비 363개 클래스 누락」이라는 중간 결과가 나왔는데 **검증 스크립트의 파싱 오류**였다
(`ds-*`·`sidebar-*` 는 Tailwind 가 아니라 프로젝트 자체 CSS이고, `mb-4` 류는 생성물에 실제로 존재했다).
전환을 실제로 판단하려면 **빌드 CSS 를 넣은 화면과 현재 화면의 시각 비교**가 필요하다.

## 5. 재발 방지

`audit:query-cost` 의 `TARGETS` 에 이번 세 경로를 추가했다(새 게이트를 만들지 않았다 — 이미 ms·KB 를 보는 감사가 있다).
**`maxKB` 가 이 프로젝트에서 페이로드 회귀를 잡는 유일한 눈금**이다 — 값을 올릴 때는 화면이 그걸 다 쓰는지 먼저 본다.

```
inventoryCounts.lastWithLoss   maxKB 20    (357KB 였던 자리)
clients.supplierPicker         maxKB 40    (218KB 였던 자리)
userPrefs.withPresets          maxKB 30    (왕복이 2로 돌아가면 여기가 먼저 깨진다)
```

⚠️ `audit:query-cost` 는 **여전히 실행 경로에 안 물려 있다**(prod 대상이라 CI·`ship:gate` 에 넣기 어렵다).
