### 4-5. 재고 파악은 원가의 전제조건이 아니다

> "일부 품목만 재고를 세고 있고 나머지는 파악이 안 되는데 어떻게 하나" (용준님 질문)

## 파트 5. MES 구조 + 장부 관리방안 (결정 3·4)

### 5-1. 결정된 방향 (용준님, 2026-08-12)

1. **초반** — 주문을 **이카운트에서 동기화**해 MES 로 들여온다
2. **1달 병행** — 두 시스템을 나란히 돌리며 숫자를 대조한다
3. **이후** — **전체 이관**하고 MES 에서 직접 작성한다

### 5-2. 동기화 수단 — 새로 만들 것이 없다

| 방법 | 상태 | 주기 | 부담 |
|---|---|---|---|
| **A. 파일 업로드** (`/migration` 화면) | ✅ **이미 구현됨** — 거래처·품목·주문·입금 preview+import, `external_order_number` 중복 방지 | 주 1회~일 1회 | 내보내기+업로드 5~10분 |
| B. 이카운트 Open API | 미구현 | 자동 | 인증키 발급 + 개발 |
| C. Chrome 세션 자동화 | 부분 | 반자동 | 세션 유지 필요·불안정 |

**→ A 로 간다.** 1달 뒤 이카운트를 놓을 계획이므로 **B 에 개발을 투자할 이유가 없다.**
한 달 쓰고 버릴 연동을 만드는 것이 가장 비싼 선택이다.

**⚠️ 내보내기 양식은 `판매현황`이어야 한다.** 보유 중인 `주문서현황내역`(15,957라인)에는
**거래처코드·품목코드가 없어** 770곳을 이름으로 매칭해야 한다(`EXPORT-SPEC.md` §2).
`판매현황`에는 둘 다 있고, `clients.client_code` 가 **사업자번호 형식으로 100% 채워져 있어** 직결 매칭된다.

### 5-3. 동기화가 살려내는 것

파트 4에서 확인했듯 **끊긴 곳은 주문 유입 한 곳뿐이다.** 주문이 들어오면 아래가 연쇄로 살아난다.

```
이카운트 판매현황  →  주문·라인(품목코드 매칭)  →  product_materials 411건
                                              →  자재 자동차감  →  라인 원가  →  품목별 마진
```

그러려면 동기화 라인에 **품목코드가 반드시 실려야 한다.** 품목이 매칭되지 않으면
주문 건수만 늘고 원가는 여전히 0으로 남는다 — 지금 `(품목 미연결) 561라인 6,374만`이 그 상태다.

### 5-4. 1달 병행에서 확인할 것 (전체 이관 판정 기준)

| 기준 | 목표 | 확인 방법 |
|---|---|---|
| 월 매출 총액 | 이카운트와 **오차 0** | 월말 대조 |
| 거래처별 잔액 | 오차 0 | `deriveClientBalance` vs 이카운트 미수 |
| 품목 매칭률 | **95% 이상** | 미매칭 라인 수 |
| 자재 차감 발동 | **0건 → 발생** | `inventory_auto_deductions` |
| 라인 원가 산출 | 상위 20품목 커버 | `order_items.material_cost` |

**이 다섯이 한 달 연속 충족되면 전체 이관.** 하나라도 미달이면 병행을 연장한다.

### 5-5. 장부를 어디에 둘 것인가 (결정 4)

| 장부 | 지금 | 이관 후 |
|---|---|---|
