# 2026-08-20 재고 base-unit 리베이스 — 사후 기록 (#615)

> ⛔ **이 문서는 실행물이 아니다.** SQL 로 만들지 않은 것도 의도다 — 아래 §재실행 금지 참조.
> 커밋 `8fdf76c` 가 prod 에 직접 적용한 보정을, 산출물 없이 커밋 메시지 한 줄로만 남겨 둔 것을
> 뒤늦게 문서로 세운다(2026-08-31).

## 무엇을 했나

커밋 메시지 원문:

> Rebased 188 items: qty x pack_size, cost / pack_size -- valuation unchanged.
> Banner fabric (AQ*) excluded: base_unit is NULL.

- 대상: `pack_size > 1` 이면서 `base_unit` 이 있는 품목 **188개**
- 규칙: `inventory.quantity × pack_size` · `items.avg_unit_cost ÷ pack_size`
- 불변식: **평가액(`quantity × avg_unit_cost`) 불변** — 축만 포장단위(롤·통)에서 base(M·yd·L)로 옮긴 것
- 제외: 현수막 원단(`AQ*`) — `base_unit` 이 NULL 이라 발주도 재고도 yd 다. 그 `pack_size=130` 은
  실사 입력 편의 계수이지 환산계수가 아니다(마이그 `0540`). 여기에 손대면 매입이 130배가 된다.

## 왜 필요했나

`0540` 의 두 칸 실사 구조가 **수량은 base 로 쓰기 시작**했는데 `avg_unit_cost` 는 여전히 포장단위였다.
축이 어긋난 채 곱해져 08-07 실사 평가액이 **4.6억(실제 3,436만)** 으로 부풀었다.

## 대상 188개 목록은 이제 복원되지 않는다

당시의 정확한 집합은 **현재 DB 에서 역산할 수 없다.** 그 뒤로 같은 컬럼을 움직인 작업이 여러 번 있었다:

| 날짜 | 작업 | 영향 |
|---|---|---|
| 08-26 | 잉크 단위 L→통 전면 통일 | 126품목의 `unit`·`pack_size`·`avg_unit_cost` 변경 |
| 08-27 | `avgcost-align` 24품목 · `base-price-axis-fix` · 환봉나무 3규격 신설 | 원가·품목 집합 변경 |

실측(2026-08-31 prod): `pack_size>1` = **193**, 그중 `base_unit IS NOT NULL` = **143**.
당시 조건과 같은 술어인데 **188 ≠ 143** 이다 — 집합 자체가 그 뒤로 달라졌다는 뜻이라,
"지금 조건에 맞는 품목"을 그때의 188개로 제시하면 그건 재구성이 아니라 **날조**다.

**복원 가능한 것은 규칙과 불변식뿐이고, 이 문서가 그것이다.**

## ⛔ 재실행 금지

이 보정은 **멱등이 아니다.** 다시 돌리면 수량에 `pack_size` 가 한 번 더 곱해지고 원가는 한 번 더
나뉜다. 평가액은 우연히 보존되지만 **수량과 단가가 각각 pack_size 배·분의 1로 틀어진다**
(원단 계열은 실측 **50배** 전례 — memory `feedback-avg-cost-backfill-axis`).
멱등 가드를 붙인 SQL 로 만들지 않은 이유가 이것이다: "가드가 있으니 돌려도 된다"고 읽히는 순간
이 문서는 사고의 원인이 된다.

## 재해복구 관점 (이슈 본문 우려에 대한 답)

"마이그레이션 재생으로 새 환경을 만들면 이 rebase 가 빠진다"는 걱정은 **성립하지 않는다.**
`migrations/*.sql` 은 **스키마**를 만들지 데이터를 만들지 않는다 — 새 환경의 재고 수량은
마이그레이션이 아니라 D1 백업 복원이나 재이관으로 들어오고, 백업에는 리베이스된 값이 이미 들어 있다.
이 보정을 마이그레이션으로 만드는 쪽이 오히려 위험하다: 이미 리베이스된 DB 에 두 번째로 적용될
경로가 생긴다(§재실행 금지).

## 지금 이 축을 지키는 것

산출물이 아니라 **상시 게이트**다. 사후 스크립트보다 이쪽이 실제 방어선이다.

- `npm run test:stock-unit` — 금액=base 단가 · 발주=포장 수량/원가 · 입고 환산 (실측 30/30 · 22항목)
- `npm run test:stock-valuation` — 화면 금액이 avg 축과 맞는지
- `npm run audit:avgcost` — 원가가 매입 실적에서 벗어난 품목을 상시 지목(⚠️ 이 감사도 "재실행은
  평가액을 바꾼다"를 스스로 경고한다)
- `npm run audit:stock-ledger` — 잔고↔원장 대사(기준선 `scripts/stock-ledger-baseline.json`)
