# 매입 실명세 요청 팩 — 공급처별 (2026-08-28)

원본 = `node scripts/lump-voucher-report.cjs` (prod 실측). 이 문서는 **요청할 내용만** 추린 것이고,
숫자가 바뀌면 스크립트를 다시 돌린다(여기 값을 손으로 갱신하지 않는다).

## 왜 이걸 받아야 하나

우리 DB의 매입 라인 중 일부는 **금액만 있고 수량이 없다**(`수량 1 · 단가 = 금액`).
세무장부에서 적재할 때 적요에 대표품명 1줄만 실려 오기 때문이다. 이 상태에서는

- 품목별 `avg_unit_cost`(평균 원가)가 서지 않는다 → **마진·원가율이 틀린다**
- 재고 평가액이 그 품목만 빠진다
- 같은 계열의 다른 품목은 매입이 0건이라 원가가 아예 없다(아래 §4)

**돈이 없어서가 아니라 명세가 없어서** 못 푼다. 그래서 사람이 공급처별로 받아 와야 한다.

## 3. ⚠️먼저 확인하고 요청할 것

**(주)엘이디포유 「원장 밖 매입」 06-30 18,250,000** — 이건 청구서 요청 대상이 **아니다**.
품명이 「원장 밖 매입 (지급 3건 대응 · 잔액으로 검증됨)」이다. 즉 **원장에 없던 것을 지급액으로 역산해
만든 라인**이라, 공급처에 물으면 "그런 계산서 없다"가 나온다.
→ 요청할 것은 계산서가 아니라 **「06월 지급 3건이 무슨 건이었는지」**다. 우리 쪽 지급 기록부터 본다.
엘이디포유의 나머지 07-31 두 줄(3,325,830 · 1,594,300 「광고물 및 제작용품 外」)은 정상 B형이다.

**(주)서울경금속 28행 5,124,540** — 24품목에 흩어진 소액이고, **품목 연결은 이미 다 돼 있다**.
평균 18만 원짜리 줄이라 명세를 받아도 원가가 크게 안 움직인다. **후순위**.

## 5. 바로 07-22 전표 잔액 4,625,000 — 요청 내용이 좁혀졌다

전표 총액 12,815,000 중 적요분 8,190,000(환봉나무 54,600 × 150)을 빼고 남은 금액이다.

**바로는 두 가지만 판다** — 환봉나무(원목 깃대봉)와 재단로프.
알려진 단가로 4,625,000 을 나눠 보면 **재단로프 37,000원만 정확히 떨어진다**:

| 후보 | 단가 | 4,625,000 ÷ 단가 |
|---|---:|---|
| **재단로프 `ACC-038`** | **37,000** | **125.0 ✅** |
| 환봉나무 90cm | 150 | 30,833.33 ✗ |
| 환봉나무 70cm | 140 | 33,035.71 ✗ |
| 환봉나무 25파이 | 350 | 13,214.29 ✗ |
| 재단로프(판다코리아) | 38,000 | 121.71 ✗ |

37,000원은 바로에게서 **두 번 확인된 실단가**다(03-24 130개 · 04-03 200개). 그리고 04-03 전표도
「환봉 + 재단로프」 혼합이었다 — 같은 구조다.

> ⛔**그래도 이대로 적용하지 않았다.** 「정수로 나눠진다」는 것 자체는 증거가 아니다
> (memory `feedback-material-cost-stock-vs-purchase`). 확인 비용이 카톡 한 줄이라 확인이 맞다.

**요청**: 바로에 **2026년 7월 거래처원장** 1장. 03·04월분은 이미 받아서 쓰고 있다.
받으면 `docs/analysis/2026-08-27-yeonggwang-lump-split.sql` 과 같은 「적요 수량줄 + 잔액줄」 방식으로 분해한다.
(원가 영향은 어차피 작다 — `ACC-038` 평균이 37,232 → 37,158 로 0.2% 움직일 뿐이다. **수량 귀속이 목적**이다.)

## 회수 후 처리

1. 명세를 받으면 `docs/analysis/YYYY-MM-DD-<공급처>-lump-split.sql` 로 분해한다.
   양식 정본 = `2026-08-27-yeonggwang-lump-split.sql` (백업 테이블 + 롤백 SQL 필수).
2. **전표 총액은 절대 바뀌면 안 된다** — 적요분만 쪼개고 나머지는 「(미상) 잔액」 줄로 남긴다.
   `purchase_orders.total_amount` = 라인 합계 불변이 검증식이다.
3. 분해 후 `npm run audit:avgcost` → `npm run report:lump` 로 줄어든 것을 확인한다.
