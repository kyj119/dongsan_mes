**누적 매출총이익률 약 50.5%.** 다만 월별로 27.9%~78.9%로 튀는데, 매입은 **발주일** 기준 덩어리라
매출 기간과 대응하지 않기 때문이다. **월 단위로는 쓸 수 없고 누적만 유효하다.**

> ⚠️ **정정 (2026-08-07)** — 이 표의 매입에는 **오다플래그 117,696,745(공급가)가 섞여 있다.**
> 용준님 확정으로 그건 **관계사 자금이동이라 매입이 아니다**(§5-7-e).
> 빼면 매입 1,466,212,522 · **매입/매출 45.8%** · 매출총이익률 **54.2%** 다.

> ⚠️ **매입 적재가 두 방식이라 그대로 합산하면 틀린다.**
> 상반기 발주는 `total_amount`(공급가)에 들어 있고, **7월 26건은 `total_amount = 0`이고
> `final_amount`(부가세 포함)만 있으며 `purchase_order_items` 라인도 없다**(세무장부 251 잔액 기준 적재).
> 위 표는 `total_amount > 0 ? total_amount : final_amount / 1.1`로 통일해 추정한 값이다.
> 상반기에도 같은 형태가 55건 섞여 있다. **`SUM(total_amount)`만 쓰면 7월 매입이 0으로 나온다.**

### 5-7. ★ 태극기 yd → 장수 환산 (2026-08-07) — 8.3억이 열렸다

태극기는 동산 매출의 **25.9%(830,136,155)** 인데 원가가 통째로 0 이었다.
원단은 `yd` 로 사고 완제품은 `장` 으로 파는데 **그 사이를 잇는 값이 없었기 때문**이다.

**잃어버린 조각 = 롤 폭.** `items.width_mm` 는 전 품목 비어 있는데
매입 라인 품명에 「T/P 75" 태극기 180*270」 처럼 **인치로 적혀 있었다.**

**배치 모델**
```
장/yd = floor(롤폭 ÷ 가로지르는 변) × (91.44 ÷ 길이 변)
yd/장 = 그 역수 → product_materials.quantity (usage_type=FIXED_QTY)
원가  = quantity × 원단 avg_unit_cost(원/yd)      ← 새 계산기 불필요
```

**어느 변이 롤을 가로지르는가** = 장/yd 가 큰 쪽(공급처가 원단을 아끼는 방향).
근거는 데이터에 있다 — `180×270@75"` · `150×225@61"` · `120×180@51"` 는 **한 변만 롤에 들어간다**

|---|---|---:|---:|---|

### ② ★ 「수량 X 단가」 뒤바뀜 — 2차에서 방향을 바로잡았다

품명 꼬리 「A X B」 에서 A 가 **수량**, B 가 **단가**인데 적재기가 **거꾸로** 읽었다.
**A×B 는 곱셈이라 금액으로는 방향을 못 가른다.** 1차에서는 `quantity = amount` 인 5행만 보고
"금액이 수량 칸에 들어갔다"로 좁게 판단했는데, 그건 A=1 인 특수 케이스였다. 근거 3가지로 확정했다:

| 근거 | 내용 |
|---|---|
| 단가 타당성 | 「무궁화 봉 중 31,660 X 130」 을 **31,660원짜리 봉**으로 읽으면 4,616원 세트의 부품이 될 수 없다. **130원**이어야 맞다. 「수기봉 80,000 X 100」 도 같다 |
| 물량 정합 | 세트 12,734개에 봉이 1개씩 든다. 뒤바뀐 값이면 무궁화 봉 매입이 **360개**뿐이라 물리적으로 불가능 → 바로잡으면 **65,040개** |
| 형제 라인 | 「기기유지보수 1 X 180,000」 = 1회 × 180,000원 — 같은 규칙 |

| 품목 | 교정 전 | 교정 후 |
|---|---:|---:|
| `GDS-FB1-FIN` 무궁화 봉 | 32,759원/개 (360개) | **181원/개 (65,040개)** |
| `ACC-041` 황금봉 | 3.52원/개 (9,997,104개) → 334,886원 | **304원/개 (115,503개)** |

- 1차에서 고친 5행(3093·3095·3108·3111·3113)은 A=1 이라 어느 쪽으로 읽어도 결과가 같아 **그대로 유효**하다.
- 예외 1행 — 「가로봉 35,500 X 230」 은 35,500×230 = 8,165,000 인데 전표는 10,598,000 이다.
  「태극기 보관함 **외 1**」 과 같은 **전표 대표품명** 형식이라 나머지 2,433,000 은 다른 품목이다.
  수량만 살리고 단가는 금액÷수량(298.5원)으로 뒀다 — 「외」 분이 섞여 약 30% 높다.
- 금액(`amount`)은 처음부터 정상이라 **회계·AP 숫자는 어느 단계에서도 영향이 없었다.** 망가졌던 건 수량·단가다.
- `load/fix_qty_amount_swap.sql`(1차) · `load/fix_qty_price_swap_round2.sql`(2차) prod 적용.
  단가 backfill 재실행 후 **바뀐 품목이 656·1493 둘뿐**임을 전후 대조로 확인.

세무장부 전표에서 온 **금액전용 라인(수량 1)** 이다. 6백만원짜리 도금 외주비가 분모에 「1개」로 들어가
수량가중평균을 망가뜨렸다.

**더 근본적으로 다른 물건이었다.** 봉은 깃대가 아니라 깃대 끝에 끼우는 장식(finial)이고 용도별 변종이다.
ACC-041 에 붙어 있던 7라인은 **가로봉·수기봉·애기봉뿐**이고 정작 무궁화봉 도금 매입은 없었다.

BOM 이 이를 확증한다 — 두 세트가 **같은 태극기 7호**를 쓴다(= 봉도 같은 크기 등급):

| 세트 | 구성 |
|---|---|
| `GDS-FBSET` 국기함세트 | 케이스 + **무궁화봉(무도금)** `GDS-FB1-FIN` 181원 + 태극기 7호 |
| `GDS-JIGWANSET` 지관세트 | 지관통 + **황금봉(도금)** + 태극기 7호 |

용준님 확인 「무궁화봉에 도금하는게 황금봉, 둘 다 동일한 크기」·「지관 세트에는 황금봉, 국기함 세트에는 기본봉」과 정확히 일치한다.

**조치 = 떼어내기.** 품명이 용도를 말하므로 추정이 아니다. 원가는 **수량이 실린 라인만 분모**로 쓰고
금액전용 도금비는 분자에만 더했다.

| 품목 | 매입 | 원가 | 산식 |
|---|---|---|---|
| `ACC-041-GA` 가로봉 | 17,096,500 | **481.56** | (10,598,000+6,498,500) ÷ 35,500 |
| `ACC-041-SU` 수기봉 | 13,968,000 | **174.60** | (8,000,000+5,968,000) ÷ 80,000 |
| `ACC-041-AG` 애기봉 | 600,000 | 0 | 금액전용 · 수량 불명 |
| `ACC-041` 황금봉 | 0 | **181.32** | 소재분(무궁화봉)만. **도금비 미식별** |

★ 황금봉 원가는 **소재분만** 넣고 도금비를 비워 뒀다. 모르는 값을 그럴듯한 숫자로 채우면
다음 사람이 확인된 값으로 착각한다 — 지관세트 원가는 그만큼 과소다.

**★ 별건으로 발견**: `E1-PO-RCH-0624` 「가로봉 35,500 X 230」의 금액이 산식과 안 맞는다.
35,500 × 230 = 8,165,000 인데 전표 금액은 **10,598,000**(차이 2,433,000). 세무장부 전표라
품명은 대표 품목만 적히고 금액은 송장 총액이 들어온 것으로 보인다. 실제 송장 확인이 필요하다.

## 8-O. 규격 표기 규칙 확정 · 부직포 롤 단위 통일 (2026-08-09 · prod)

### ① 규격 = 「그 계열에서 변하는 축」만 (용준님 확정)

용준님 지시 그대로 — **「트러스바는 7m 가 기본이므로 200·250·300 으로 규격을 분리」.**

| 계열 | 고정(넣지 않음) | 규격 |
|---|---|---|
| 트러스바 · 채널바/트러스 옆마구리 | **7m** · **100mm** · 색 | `150mm` … `400mm` |
| 입체바 80mm / 100mm | **3m** · 1.0T · 색 | `80mm` / `100mm` |
| 캡바 | 3m · 색 | `25mm` (계열을 가르는 유일한 치수라 남김) |
| 트러스바 날개 | 색(품명에 있음) | (비움) |

예외 — 두 치수가 **둘 다 변하면** 둘 다 적는다(`SGM-CSM-R200X113-*` → `200*113mm`).

**★ 기존 MES 품목은 이미 이 형식이었다**(`150mm`·`200mm`). **내가 신설한 13종만** 섞어 넣었다.
계열 전체 132건을 훑어 통일했다.

**왜 중요한가** — 섞어 적으면 둘이 깨진다:
① 매칭기가 「200mm*7m 진회색」과 「200mm」를 **다른 규격**으로 본다. 실제로 이 때문에 트러스바 계열이
갭 워크시트에서 「신설 후보」로 잘못 분류돼 **하마터면 중복을 대량 등록할 뻔했다.**
② 규격 필터·정렬이 문자열이라 `200mm` 와 `200mm*7m` 이 갈린다.

### ② 부직포 = 롤(50m) 고정 (용준님 확정)

같은 거래가 롤로도 yd 로도 적혀 `avg_unit_cost` 가 무의미했다(60폭 63,750 / 152폭 4,219).
실제로는 **금액이 같고 수량·단가만 다른** 같은 물건이었다 —
60폭 `70yd × 1,020 = 71,400` = `1롤 × 71,400`, 127폭 `100yd × 2,220` = `2롤 × 111,000`.

판별은 **단가 크기**로 했다. 50m 롤 = 54.68yd 라 롤 단가가 yd 단가의 50배 대다 —
1만원을 경계로 두면 실측 범위(yd 1,020~2,820 · 롤 60,000~222,000)가 겹치지 않는다.
yd 라인 8건을 롤로 환산(수량 ÷ 54.68), 나머지 14건은 단위 표기만 '롤' 로 맞췄다.

**⚠️ 금액은 한 건도 바꾸지 않았다.** 매입액은 세금계산서와 맞아야 하는 값이고,
고친 건 「몇 개를 샀나」의 단위뿐이다.

## 8-R. 쓰기 스모크 신설 — 읽기 111개가 못 잡던 것 (2026-08-09)

### 왜 필요했나

`sales_rep_id` 를 추가하면서 컬럼·플레이스홀더는 32개로 늘리고 `.bind()` 값은 **31개**로 뒀다.
D1 은 개수가 정확히 맞아야 해서 **`POST /api/orders` 가 전부 던졌다** — 주문 생성이 통째로 죽었다.
그런데 배포 후 `npm run smoke` 는 **110/110 통과**했다. **읽기 전용**이기 때문이다.
111개 GET 을 다 돌아도 바인드 개수 불일치·NOT NULL 위반·FK 오류는 한 건도 안 잡힌다.

실사용 주문이 아직 0건이라(전체 주문의 `created_at` 이 전부 이관분 `09:00:00`) **피해는 없었지만,
잡아낸 게 아니라 운이었다.** 다른 세션의 자동 감사가 먼저 찾아 고쳤다.

### `npm run smoke:write` — 생성 → 조회 검증 → 삭제 → **제거 확인**

주문·발주·거래처 3경로. 첫 실행부터 **자기 설계의 결함 3개**를 잡았다:

| 발견 | 내용 |
|---|---|
| entity 99 로는 못 지운다 | `DELETE /api/orders/:id` 가 `entityFilter` 로 타 법인 삭제를 막는다(IDOR 방지 #333, **정상 동작**). `entityId` 는 JWT 에서 오고 헤더로 못 바꾼다 → **세션 법인에 만들고 지우는** 설계로 변경 |
| 발주는 응답 계약이 다르다 | 주문은 `200`·`data.id`, 발주는 **`201`·`data.po_id`**. 200/`data.id` 만 기대해 **정상 생성을 FAIL 로 읽었고**, FAIL 이라 정리 목록에 안 들어가 **잔재가 남았다** |
| 정리 PASS 가 거짓 안심이었다 | 주문은 **2단계 삭제**다(1차 `CANCELLED` → ADMIN 이 한 번 더 부르면 하드 삭제). 한 번만 불러 CANCELLED 로 남았는데 **상태코드만 보고 PASS** 로 찍었다 → 정리 후 **GET 으로 실제 제거를 확인**하도록 변경 |

### 스모크가 드러낸 **본체 결함 2건도 고쳤다** (prod 배포 완료)

**① 발주가 body 의 `entity_id` 를 무시했다.** `entity_id: 99` 를 보내도 `getEntityId(c) || 1` 로
**세션 법인에 생성**됐다 — E2E 가 실법인을 오염시키는 경로였고, 코디네이터가 타법인 발주를 접수할 수도 없었다.
주문 생성과 **동형**으로 고쳤다(명시값 > 세션). ★ **채번도 같은 값**을 쓰게 했다 —
주문에서 겪은 불변식 「번호 E{eid} = 행 entity_id」가 발주에도 그대로 적용된다.
안 맞추면 `E1-...-P001` 번호를 단 행이 `entity_id=99` 로 앉는다.

**② 번호 시퀀스 소진이 사라졌다.** `POST /api/auth/switch-entity` 가 **새 JWT** 를 준다는 걸 확인했다
(`entities` 에 99 「E2E 테스트」가 이미 등록돼 있다). 99 세션이면 `entityFilter` 도 99 라 **삭제까지 통과**한다.
전환 실패 시엔 **중단**한다 — 실법인에 만들 바에는 안 도는 게 낫다.

**검증** — 발주가 `E99-20260809-P001` 로 생성됐고(고치기 전엔 `E1-...`),
당일 실법인(1·2·3) 번호 소진 **0건**, 잔재 **0건**, 스모크 **3/3 PASS · 정리 3/3**.

**그래서 워크시트가 아누코를 「미등록」으로 잡았다** — 감사·워크시트는 활성 품목만 보기 때문이다.
후보로 엉뚱한 브랜드(프라임 `PJ-HAP-*`)가 올라온 것도 그 탓이다.
용준님이 프라임을 채택하신 건 **아누코가 단종이라 프라임으로 대체**한다는 뜻으로 읽었고 그대로 반영했다.

⚠️ 비활성 16종은 그대로 뒀다 — 이관 이력의 흔적이고, 되살릴지는 운영 판단이다.

### ② 스카시 — 매입=원판, 판매=제품 (백색 기본)

**이카운트는 둘을 안 나눴다** — 「스카시10T/20T/30T/50T」 넷뿐이고 **색도 없다.**
MES 는 원판(`SKS-<t>T-<색>-36`)과 제품(`UV-SKS-<t>T-<색>`)이 갈려 있다.

용준님 확정대로 **백색을 기본**으로 잡았다:

| 맥락 | 코드 |
|---|---|
| 매입 | `SKS-<t>T-W-36` (원판 3x6) |
| 판매 | `UV-SKS-<t>T-W` (UV 제품) |

50T 만 원판은 있는데 제품 코드가 없어 `UV-SKS-50T-W` 를 신설했다(10/20/30T 는 짝이 맞았다).
품목맵에 매입 12키를 넣었다 — **매입 이관용 맵이므로 원판이 정본**이고, 판매는 `gen_e2_h1_link` 규칙이 제품으로 보낸다.

### ③ 포맥스 — **축이 서로 다르다.** 확인이 필요하다

| | 축 | 종수 |
|---|---|---|
| 이카운트 | **국산/중국산** × 크기(3*6·4*8) × 두께 | 20 (색 없음) |
| MES | **백색/검정** × 두께 × 크기 | 22 (브랜드 없음) |

용준님 모델(예스=중국산 · 포마트=국산 × 2·3·5·8·10T × 3*6·4*8 = **20종**)은 **이카운트 축과 같다.**

**★ 색 축은 실적이 없다** — 실적이 붙은 FMX 6종이 **전부 백색**이고(15T·1T·2T×2·3T·5T),
검정 10종은 매입 0 · 판매 0 이다. 이카운트도 색을 안 쓴다. 그래서 브랜드 축으로 재편해도 잃는 게 없다.

**이카운트 현재 등록 상태(20종)**

| | 3*6 | 4*8 |
|---|---|---|
| 국산(포마트) | 1·2·3·5·8T (**10T 없음**) | 1·2·3·5·8·10T ✅ |

## 8-V. 포맥스 브랜드 축 재편 (2026-08-09 · prod)

용준님 「가」 확정 — **브랜드 축으로 재편**했다.

| 처리 | 종수 | |
|---|---|---|
| 신설 | **20** | `FMX-YES-<t>T-<36/48>`(예스·중국산) · `FMX-PMT-…`(포마트·국산) × 2·3·5·8·10T × 3x6·4x8 |
| 유지 | 6 | 실적 있는 것 — 품명에 **「(브랜드 미상)」** 표시 |
| 비활성 | 16 | 실적 없는 색 변종 |

**★ 실적 있는 6종을 옮기지 않았다.** 어느 브랜드인지 모르는데 임의로 배정하면 **원가가 딴 브랜드에 붙는다.**
품명에 「(브랜드 미상)」을 달아 신규 코드와 눈으로 갈리게만 했다. 브랜드를 아시면 그때 옮기면 된다.
1T·15T 는 애초에 20종 범위 밖이라 그대로 남는다.

**비활성은 조건으로 이중 확인했다** — `NOT EXISTS(매입) AND NOT EXISTS(판매)` 를 SQL 에 박아,
실적이 붙은 게 하나라도 있으면 애초에 안 꺼지게 했다. 삭제가 아니라 플래그라 되살리기도 쉽다.

품목맵에 **37키** 추가(556 → 593). 이카운트 표기 「포맥스-국산 4*8(3T)」가 `FMX-PMT-3T-48` 로 간다.

**⚠️ 1T 는 넣지 않았다** — 지시 범위(2·3·5·8·10T) 밖이라서다. 그런데 **이카운트엔 1T 가 4종 있다**
(국산 3*6·4*8 · 중국산 3*6·4*8). 기존 `FMX-1T-W-48` 에도 실적이 1건 있다.
1T 를 브랜드 축에 넣을지는 별도 판단이 필요하다.

감사 통과 — `audit:new-items` 중복 0 · `audit:items` 게이트 위반 0 (활성 1,210종).

## 8-W. 포맥스 1T 추가 · **비활성 후보 노출** (2026-08-09 · prod)

### ① 포맥스 1T — 브랜드 축에 편입

1차엔 지시 범위(2·3·5·8·10T)를 지켜 뺐는데, 이카운트에 1T 가 4종 있고 기존 `FMX-1T-W-48` 에도
실적이 1건 있어 실재하는 규격이다. `FMX-YES-1T-36/48` · `FMX-PMT-1T-36/48` 신설, 맵 8키 추가(593 → 601).
브랜드 축 = 예스 12 · 포마트 12 = **24종**.

### ★ ② 아누코가 드러낸 근본 결함 — 갭 표가 **오답을 유도하고 있었다**

갭 워크시트는 **활성 품목만** 후보로 올렸다. 그래서 아누코 16종이 MES 에 있는데도 「미등록」으로 잡히고
**엉뚱한 브랜드(프라임)가 1위 후보**로 나왔다. 그걸 보고 판단하면
「단종된 자기 브랜드」가 아니라 「남의 브랜드」에 붙는다 — **표가 틀린 답을 유도한 것이다.**

비활성도 후보에 넣고 **`[중단]` 을 붙였다.** 이제 이렇게 나온다:

```
합성지(30m)-아누코  60폭  → SYN-AN-060   [중단] 합성지(30m)-아누코 / 60cm   [기존연결 유력]
```

「되살릴 것인가 · 대체할 것인가」를 **사람이 고를 수 있게** 됐다. 이건 아누코만의 문제가 아니다 —
`LC6771M → SK-1887 [중단]` · `간판 → SGM-BOARD [중단]` 처럼 다른 계열에서도 즉시 드러났다.

## 8-X. 대표 코드 판매 배분 — 마진이 나오기 시작했다 (2026-08-09 · prod)

매입은 규격별 코드로 들어가는데 **판매만 대표 코드**에 붙어 있어 마진이 계산되지 않았다.
**207라인을 규격별로 배분**했다.

### 무엇을 배분하고 무엇을 남겼나 — 실측으로 갈랐다

**배분함** — 판매 규격이 **자재 규격 그대로**인 것

| 대표 | 라인 | 규격 |
|---|---|---|
| `SGM-SMPS` | 128 | `100W`~`500W` → `SGM-SMPS-W100~W500` (MES 에 전부 있었다) |
| `SGM-LEDF` | 79 | `20W-단면`·`20W-웜`·`28W-양면/돌출`·`30W-양면` → `F20S/F20W/F28D/F30D` |

30W 는 MES 에 없어 `SGM-LEDF-F30D` 를 신설했다. 표기 흔들림(`300W`/`300w` · `28W-양면/돌출`/`28w-양면(돌출)`)은
정규화로 흡수했다. 보류 1라인은 규격이 빈칸이라 근거가 없다.

**★ 트러스바 50라인 14,204,000 은 일부러 뺐다.**
규격이 `9730x200mm` 처럼 **완성 크기**다. 뒤 숫자가 폭이라 `-R200-` 계열까지는 좁혀지고,
폭이 원가를 지배하는 것도 맞다(150폭 57,800 → 400폭 220,000 · 3.8배, 색 편차는 ±10%).
그런데 **판매는 재단품이고 자재는 7m 원장**이다. 붙이면 「9730mm 1건 = 1개 팔림」이 되어 **수량이 왜곡된다.**
제대로 하려면 BOM(재단품 = 원장 × 길이비율)이 필요하고 그건 별건이다 —
**수량이 틀리는 연결은 안 하느니만 못하다.**

같은 이유로 `SV-MESH`·`SV-TENT`·`AQ-TENT` 도 손대지 않았다. 그건 **제품**(출력물)이고
`SVM-*`·`SVT-*`·`TENT-*` 는 **원단**이라 대표 코드가 맞는 자리다(§8-N).

|---|---|---|

### ★ 배분이 기존 오연결을 드러냈다

`SGM-LEDF-F28D` 원가율이 **81%** 로 혼자 튀어 들여다보니, 규격 「20w-단면」인 라인 하나가
28W 코드에 붙어 있었다(id 2979 · 300,000원). **내 배분이 만든 게 아니라 그 전부터 있던 오연결**이다 —
배분해서 원가율이 계산되기 전에는 볼 방법이 없었다. 교정 후 72%.
