> 2026-09-15 시작 조건 충족(J0~J7 36단계 3사이클 + 제안 P1~P12 전부 판정). 기간 **2주**. 정본 절차 = `/journey-loop` 스킬.
> 원칙: 막지 않는다(불편은 기록하고 계속 쓴다) · 판정은 재현으로만(「어색하다」는 제안 축) · 고친 것은 반드시 여정 단계로 승격.

## 2. 결함 기록 — 이 네 줄이면 여정이 된다

```
화면:          (예 /order-form)
하려던 것:      (예 견적서에서 넘어온 주문에 라인 하나 추가)
실제로 된 것:   (예 저장 뒤 규격이 사라짐 · 문구 「…」 · 아무 반응 없음)
다시 하면 또?:  예 / 아니오 / 가끔
```
어디에: 카톡 「MES 병행」 방 또는 `docs/journeys/PROPOSALS.md` 에 P번호로. **재현이 되는 것만 결함**, 안 되는 것은 제안(P)으로 남긴다.

## 3. Claude 쪽 일일 루틴

1. 아침 `JOURNEY_BASE_URL=http://localhost:3001 npm run journey:cycle` (또는 `/loop`) — 36단계 통과 확인.
2. 기록된 결함 → 재현 → 안전 수정 화이트리스트 안이면 고치고 **여정 단계 추가** → 배포(`ship:gate` 가 여정을 돌린다).
3. 화이트리스트 밖(구조·정책)은 PROPOSALS 에 P번호로 올리고 용준님 판정을 받는다.
4. 주말: 2주 뒤 판정 재료를 센다 — 직원별 MES 직접입력 주문 수(`orders.created_at` 이 09:00:00 이 아닌 것) · 결함 건수 · 여정 단계 수.

## 4. 2주 뒤 판정 기준

- MES 직접입력 주문이 **주 10건 이상**이고 결함 재현율이 떨어지면 → 전환(이카운트 병행 종료 검토 · 보안 묶음 P6 착수).
- 직접입력이 안 늘면 → 화면이 아니라 **업무 순서**가 문제다(08-25 「6월 급락」 오독 교훈) — 이름 옆에 「왜 안 썼나」 한 줄부터.
