## 2026-09-11 배포 검증에서 추가

| # | 축 | 현상 | 재현 | 판단 근거 | 판정 |
|---|---|---|---|---|---|
| P6 | 운영/보안 | **prod 의 로그인 한도는 간헐적으로만 걸린다** — 같은 계정 12회 연속 틀리기: `401×7 → 429 → 401×2 → 429 → 401`(로컬은 정확히 6번째 429). `middleware/rateLimit.ts` 가 **isolate 메모리** 카운터라 Cloudflare 가 요청을 다른 isolate 로 보내면 각자 0부터 센다 → 실효 한도 ≈ 5 × isolate 수. **기존 IP 방식도 같은 성질**이었으므로 이번 변경(P5)의 회귀는 아니다 | prod 에서 존재하지 않는 계정으로 60초 안에 10번 이상 | 무차별 대입 방어가 「있다」고 믿으면 안 된다. 제대로 하려면 상태를 isolate 밖에 둔다 — Cloudflare **Rate Limiting 바인딩**(wrangler `[[ratelimits]]`, 계정·IP 키) 또는 D1/KV 카운터. 로컬 여정 J0 는 단일 workerd 라 계속 정확히 잡는다 | ③ 보류(09-11) — 「보안강화=실사용 전환 시」로 이미 정한 묶음(`project-full-review-2026-09-03`, #626 평문PW 수용과 같은 축)에 넣는다. 병행테스트 진입을 막지 않는다. 전환 시 Rate Limiting 바인딩 우선 검토 |

## 2026-09-11 사이클 2 (J5 실사·J6 견적→주문 신설 중 발견)

| # | 축 | 현상 | 재현 | 판단 근거 | 판정 |
|---|---|---|---|---|---|
| P7 | UI 결함 | **견적서에서 품목 검색칸에 Enter 를 치면 폼이 제출된다** — 검색 대신 「1개 품목의 단가가 0원입니다. 계속하시겠습니까?」 확인창. 「확인」이면 **반쯤 채운 견적이 저장**된다. 주문서는 Enter=검색(itemRow.js keydown) | /quotation-form 품목칸에 「현수막」 입력 후 Enter | `quotationForm.js` 의 품목칸에 `input` 리스너만 있고 keydown 이 없어 `<form>` 기본 제출. 거래처칸은 Enter=검색이라 영업은 같은 손버릇으로 친다 | ✅ 고침(09-11) — Enter=검색 실행, 주문서와 동일. 회귀 = J6 「견적서 작성·저장」 |
| P9 | UI 부재 | **완전 출고된 주문의 출고 취소에 화면에서 닿을 수 없다** — 주문이 SHIPPED 가 되면 카드 보드가 카드를 숨기고(`exclude_order_status=SHIPPED`), `/cards/:id` 엔 출고 버튼만 있다. 보드 모달의 「출고 취소」는 부분 출고(주문이 아직 SHIPPED 아님) 카드에서만 보인다. `/shipments` 는 `PATCH /:id/status CANCELLED` API 는 있으나 상태 변경 UI 는 확인 못 함 | 카드 출고 → 보드에서 카드 검색 | 환원 로직(`restoreStockLinesOnUnship`·STOCK_RESTORE 로그)은 세 경로(카드 unship·주문 core·출고 취소) 다 있는데 **누르는 곳이 없다**. 병행테스트에서 「잘못 출고했다」가 나오면 첫날 막힌다. J2 는 API 로 환원만 검산 | ⏳ 용준님 판정 — 카드 보드에 「출고됨」 필터 또는 주문 상세에 「출고 취소」 버튼 |
| P10 | UX | 주문서에서 거래처를 안 고르고 저장하면 앱 문구(「거래처를 선택하세요」) 대신 **「선불/착불」 select 의 브라우저 required 말풍선**이 먼저 뜬다(기본 배송방법=대신택배 → 선불/착불 required, 기본값 빈칸). 제출 이벤트 자체가 안 떠서 앱 검증(거래처→납기→…)이 한 번도 안 돈다 | /order-form 에서 품목만 채우고 저장 | 진짜 빠진 건 거래처인데 말풍선은 선불/착불을 가리킨다 — 영업이 헤맨다. 선불/착불 기본값을 두거나(택배=선불), required 대신 앱 검증에 합류 | ⏳ |
| P8 | 관찰 | 견적서 품목 검색은 `type=sales` 만 걸어 「현수막」 결과가 **50행**(주문서는 `excludeType=MATERIAL` 로 6행). 자재·원단이 섞여 나올 수 있다 | 같은 검색어를 두 화면에서 | 견적에 자재를 넣을 일이 없다면 주문서와 같은 필터가 맞다 — 영업 확인 필요 | ⏳ |
