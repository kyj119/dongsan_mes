# 여정 루프 — 제안 대장 (자동 수정 밖의 발견)

> 한 건 1줄: 현상 · 재현 · 판단 근거. 코드는 여기서 안 고친다 — 용준님이 ①고침 ②정책 유지 ③보류를 고른다.
> 정본 절차 = `/journey-loop` 스킬. 자동 수정 화이트리스트에 드는 것은 여기 오지 않고 바로 커밋된다.

## 2026-09-11 사이클 1 (J1~J4 16단계 통과)

| # | 축 | 현상 | 재현 | 판단 근거 | 판정 |
|---|---|---|---|---|---|
| P1 | API 응답 | 입금 등록에서 「1분 이내 동일한 결제」 거절이 **500** 으로 나간다(`ar-payments.ts` `DUPLICATE_PAYMENT` throw → catch 500). 화면 토스트에는 메시지가 실리지만 로그·모니터링엔 서버 오류로 집계된다 | 같은 거래처·같은 금액으로 1분 내 두 번 입금 | 업무 규칙 거부는 4xx(409/400)가 관례. 응답 형식 변경이라 자동 수정 금지 축 | ⏳ |
| P2 | UI | 현장 카드 보드에서 카드를 체크하면 하단 고정 바(`#bulkBar`)가 뜨는데, 상단 툴바의 「일괄 변경」 버튼이 화면 아래쪽으로 밀리면 그 바에 **가려져 클릭이 안 된다**(1440×900 실측). 사람은 하단 바의 「✓ 출력완료」를 쓰므로 실사용 영향은 작다 | /cards 에서 카드 체크 → 상단 「일괄 변경」 클릭 | 같은 기능이 두 곳에 있어 한쪽이 죽어도 티가 안 난다 — 상단 셀렉트+버튼을 없애거나 바 위로 올릴지 결정 | ⏳ |
| P3 | 규칙 확인 | 출력대기(PRINT_PENDING) 카드는 보드·상세 모달 어디에도 개별 버튼이 없다 — 출력중 전환은 에이전트(print_events)가 하고, 사람은 체크→일괄 변경만 가능 | /cards 에서 PRINT_PENDING 카드 클릭 | 설계(자동 추적)로 보이나 병행테스트 때 출력실이 「버튼이 없다」고 할 수 있다 — 안내 문구 1줄이면 충분한지 확인 | ⏳ |
| P4 | 시각 | `cards.shipped_at`·`orders.shipped_at` 이 UTC(`CURRENT_TIMESTAMP`)로 저장된다(실측 KST 01:49 → `16:49`). 표시가 변환한다면 정상, 안 하면 출고 시각이 9시간 어긋난다 | 출고 후 DB 조회 | memory `reference-kst-helpers` 가 `date('now')` 금지를 적어 두었는데 datetime 컬럼의 저장 축이 어디까지 KST 인지 정본 확인 필요 | ⏳ |
| P5 | 운영 | 로그인 API 가 IP 당 10회/분 — 병행테스트 기간에 같은 공유기 뒤의 직원 여러 명이 아침에 동시에 로그인하면 3~4명째부터 「요청이 너무 많습니다」 | 60초 안에 11번 로그인 | 사무실 NAT 는 한 IP 다. 한도가 IP 기준이면 직원 수만큼 여유가 있어야 한다 | ⏳ |
