# 재작업 처리 규칙 (오퍼레이터·디자이너용)

> 확정 2026-08-05. 재작업을 **MES 기능으로 만들지 않고 운영 규칙으로 처리**하기로 한 결정에 따른 절차서.
> 관련 = `docs/CUT_PANEL_USAGE.md`(재단 패널) · auto-memory `design-irregular-nesting`(주문 연결 결정)

재작업에서 사고가 나는 지점은 **파일명**이다. 출력완료 매칭이 파일명 꼬리의 `주문번호-순번`으로
`print_file_map` 을 찾는데(`src/routes/printEvents.ts:105-140`), 그 등록 행은 **에이전트가 파일을 만들 때만**
생긴다(`IllustratorAutomat/Program.cs` `RegisterFileMapAsync`). 손으로 옮긴 파일에는 그 행이 없다.
**경로에 따라 파일명을 바꿔야 할 때와 절대 바꾸면 안 될 때가 갈린다** — 아래 판단 순서를 먼저 볼 것.

---

## 판단 순서 — 질문 2개

```
Q1. 파일을 다시 만드는가?
   ├─ 예  ──────────────────────────→ [경로 A] 재등록
   └─ 아니오(같은 파일 재사용)
        └ Q2. 출고 전이고 무상(자사 귀책)인가?
             ├─ 예  ────────────────→ [경로 B] 기존 주문 유지
             └─ 아니오(출고 후 or 유상) → [경로 C] 복사 + 파일 수동
```

| | 경로 A 재등록 | 경로 B 기존 주문 유지 | 경로 C 복사+수동 |
|---|---|---|---|
| 파일명 | 자동(손댈 것 없음) | **건드리지 말 것** | **새 주문번호로 교체** |
| 출력완료 | 자동 | 자동 | **수동 체크** |
| 매출 | 새 주문 | 불변 | 새 주문(무상이면 단가 0) |

---

## 경로 A — 재등록 (파일을 다시 만드는 경우)

디자인 오류 · 규격 변경 · 칼선 수정

1. **디자이너**: 패널에서 수정 → **[주문 등록]** (거래처 · 수량 · **품목** 입력)
   - 품목이 주문 라인의 **내용**이 된다. 비우면 주문서·카드·출력 파일명에 식별 정보가 남지 않는다.
2. **오퍼레이터**: 새 주문 작성 (또는 원 주문 복사 후 **복사된 라인 삭제**)
3. **가공 대기함**에서 새 등록분을 라인으로 불러오기 → 품목·단가 확인
4. 저장

→ 주문폴더 · EPS+DXF · 파일명 · 매칭 · 출력완료가 **전부 자동**. 파일을 손으로 옮길 일이 없다.

> ⚠️ 복사를 썼다면 라인 삭제 후 **합계 금액을 확인**하고 저장할 것 — 복사가 원본 금액을 헤더에 실어온다.

---

## 경로 B — 기존 주문 유지 (출고 전 + 무상 + 같은 파일)

1. 카드에서 **되돌리기** — `출력완료 → 출력대기`. RIP 상태와 출력완료 체크가 함께 초기화된다
   (`src/routes/cards/lifecycle.ts` 카드 revert).
2. 주문폴더의 **원본 파일을 그대로** 다시 출력
3. 끝 — 출력완료가 **자동으로 다시 잡힌다**(등록 행이 그대로 있으므로 원래 카드에 정상 매칭).

> ⚠️ **파일명을 절대 건드리지 말 것.** 그대로여야 매칭이 맞는다. 경로 C의 "꼬리 교체"를 여기 적용하면
> 오히려 매칭이 깨진다.
> ⚠️ 카드를 되돌려도 라인의 출고 가능 표시(`shipment_ready`)는 **되돌아가지 않는다**(0→1 단방향).
> 재출력 전에 출고되지 않도록 주의.
> ⚠️ 주문 상태가 `출력완료`로 남아 카드와 어긋나 보일 수 있다(재계산 결과가 없으면 기존 상태 유지).
> 표시상의 불일치이며 재출력이 끝나면 정리된다.

---

## 경로 C — 복사 + 파일 수동 (출고 후 or 유상 + 같은 파일)

1. 원 주문 **복사** → 재작업 주문 생성
2. **금액 처리** — 무상이면 **단가 0으로 수정**
   - ⚠️ 복사는 원본 금액을 그대로 가져온다. 안 고치면 **매출이 이중 계상**된다.
3. 원본 파일 찾기 — Z: 출력 폴더에서 **원 주문번호로 검색**(파일명 꼬리에 주문번호가 있다)
   - DXF 경로는 원 주문 상세의 **`✂DXF` 배지 클릭 = 경로 복사**
4. 새 주문폴더에 **복사**(잘라내기 금지) 후 **파일명 꼬리의 주문번호만** 새 주문번호로 교체
   - `…-6EA-{원주문번호}-001.eps` → `…-6EA-{새주문번호}-001.eps`
   - 순번(`-001`)은 아무 값이어도 무방하다(등록 행이 없어 어차피 파일명 매칭 단계로 넘어간다).
   - **EPS·DXF 를 같은 이름으로 유지** — 재단기가 짝을 이름으로 찾는다.
5. 카드에서 **출력완료를 수동 체크**

### 금지 3가지 (경로 C 한정)

| 금지 | 결과 |
|---|---|
| 꼬리를 **그대로** 두고 복사 | 원 주문 카드에 출력완료가 찍혀 **실적 오염** — 재작업분이 원본 실적으로 둔갑 |
| 꼬리를 **잘라내기** | 주문번호가 사라져 이벤트 추적이 완전히 끊긴다 |
| 원본 폴더에서 **잘라내기(이동)** | 원 주문 이력 파손 — 반드시 복사 |

---

## 공통

- 재작업 주문(경로 A·C)의 **비고**에 `재작업: {원 주문번호} / 사유` 를 기록한다.
  시스템 링크가 없어 **원본과 잇는 유일한 수단**이다.
- 경로 B 는 기록이 거의 남지 않는다(출력 이벤트가 두 번 찍히는 것이 유일). 재작업 사실을 남겨야 하면
  주문 비고에 수기로.

## 한계 (알고 쓸 것)

| 한계 | 영향 |
|---|---|
| 경로 C 의 출력완료 자동 체크 불가 | 매칭 등록 행은 에이전트가 파일을 만들 때만 생성된다 |
| 재작업 원가·자재 손실 미집계 | 경로 B 는 특히 어디에도 안 잡힌다 |
| 원 주문 ↔ 재작업 주문 링크가 비고 텍스트뿐 | 재작업 빈도·비용 집계 불가 |

→ **경로 C 의 빈도가 늘면** 주문 복사에 **파일 연결 승계**(`ai_analysis_id`·`ai_file_id` + `order_ai_files` 복사)를
넣어 C 를 A 처럼 자동화하는 것이 가장 효과가 크다. 그러면 에이전트가 새 주문번호로 파일과 등록 행을 다시
만들어 폴더 찾기·이름 교체·수동 체크가 모두 사라진다.

## 전제 (배포 상태)

경로 C 3번의 **`✂DXF` 배지**와, 재단 시트 등록 시 **DXF 가 주문폴더로 자동 복사되는 동작**은
2026-08-05 구현분이다. 웹·에이전트·패널 배포가 끝나야 화면에 나타난다 — 그 전에는 DXF 경로를
Z: 등록 폴더(`Z:\DESIGNS\IA-등록\<건별>\`)에서 직접 찾아야 한다.
