# Z: 작업파일 → 주문서·카드 자동 생성 — 타당성 백테스트 (2026-08-11)

> 📘 **처음 보신다면 [HOW-IT-WORKS.md](HOW-IT-WORKS.md) 부터** — 이카운트 연계 방식·카드 생성 방식을
> 용어 없이 설명한 문서입니다. 이 README 는 수치와 근거 정본입니다.

**결론: 파일에서 주문서·카드 초안을 만드는 것은 성립한다.** 단 자동 확정은 금지 — 사람이 트레이에서 확인하는 구조여야 한다.

이카운트를 **정답지**로 삼아 7개월치를 오프라인 채점한 결과다. 실시간 연결도 API도 쓰지 않았다.

## 왜 이 검토를 했나

MES 실사용 전환의 관문은 "경리가 MES에 매출을 직접 입력할 수 있는가"인데, 병행입력은 부담이 크다.
대안으로 **이미 존재하는 Z: 작업파일에서 주문을 역으로 복원**할 수 있는지 본 것이다.
파일은 이카운트보다 정보가 많고(규격·후가공·납기·배송), **접수 시점**에 생긴다(이카운트 판매전표는 출고 후).

## ★ 핵심 교훈: 조인 단위는 파일이 아니라 「주문 그룹」이다

파일 1개와 이카운트 1라인은 **애초에 1:1이 아니다**. `(600x70-1장)` 파일 7개 = 이카운트 `7장` 1라인.
파일 단위로 재면 구조적으로 낮게 나온다:

| | 파일 단위 | 그룹 단위 |
|---|---|---|
| 배정률 | 45.8% | **90.7%** |
| 모호 | 30.0% | **2.0%** |
| 수량 일치 | 62.4% | **79.0%** |

**그룹 키** = 같은 날 + 같은 접수순번(`27-…`). 순번이 없으면 가장 안쪽 폴더명, 전사축은 거래처.

> ⚠️ 주문 단위 집계는 **반드시 주문으로 되접어** 세라. 한 주문에 여러 그룹이 붙어서,
> 그룹별로 세면 같은 라인을 중복 계산한다(초판이 라인 5,151·일치 43.0%로 나왔던 게 이 오류. 실제는 2,021·80.8%).

## 기각된 가설 — 순번 결정적 조인

파일명 선두 `27-`이 이카운트 `일자-No.`의 No.와 같을 것이라 보고 검증했으나 **규격 일치 3.5%로 기각**.
파일 순번은 *그날 출력 작업 순서*, 이카운트 No.는 *전표 입력 순서*로 서로 다른 체계다.
→ 규격(w×h)을 앵커로 쓰는 퍼지 매칭이 정답. 규격은 숫자라 표기가 흔들리지 않는다.

## ★ 규격 복원 = BoundingBox × 배율

EPS 헤더 `%%BoundingBox`는 **100% 판독**되지만 그대로 쓰면 틀린다. 큰 출력물은 축소해 작업하기 때문이다.
배율은 이산값(1·2·5·10)이고 **제품유형으로 거의 결정된다** — 학습 표본 1,329건의 스냅 성공률 100%.

| 제품유형 | 배율 |
|---|---|
| 게시대 · 현수막 · 250폭 · 300폭 · 투코팅 | ×5 |
| 솔벤시트 · 패트 · 폼보드 · 평판 · 매쉬배너 | ×1 |
| 솔벤현수막 · uv후렉스+비 | 혼재(크기에 따라) |

정본 = `scale_table.csv`. MES `order_items.scale_factor` 와 같은 개념이다.

전사   디자인엠투 전국당구대회(50-150-40조).eps        ← 제품유형·순번 없음

## ★ 커버리지의 진짜 병목은 축이 아니라 배정 방식이었다 (2026-08-11 2차)

커버리지 58.8% 를 "스캔 축이 3개뿐이라서"로 보고 축을 늘리려 했는데, **먼저 미커버 주문을 갈라 보니 틀린 진단이었다**:

| 미커버 701건의 정체 | |
|---|---|
| (A) 규격이 스캔 파일에 **아예 없음** = 축 누락 | 84건 (12%) |
| (B) 규격은 있는데 못 붙음 = **조인 문제** | 617건 (88%) |
| └ 그중 **같은 날** 그 규격 파일이 있음 | 465건 |

원인은 v3 이 그룹마다 **독립적으로** 최고 후보를 골랐다는 것. 흔한 규격(600x70 현수막 등)을 가진
그룹들이 전부 같은 주문 하나로 쏠려 1,794 그룹이 주문 768개에 몰렸다(1.92:1).
→ 모든 (그룹, 주문) 쌍을 점수화해 **점수 내림차순 1:1** 로 배정하니 유효 커버리지 45.1% → **58.8%**.

점수 = 규격 겹침×3 + 거래처×2 + 제품유형×1 − 날짜차×0.4

### 시도했으나 효과 없던 것 (같은 실수 반복 방지)

| 시도 | 유효 커버리지 | 판정 |
|---|---|---|
| 전역 1:1 배정 | 45.1% → **58.8%** | ✅ 채택 |
| `☆간판`·`★시트 CUT★` 축 추가 | 58.8% → 58.0% | ❌ 되레 손해 |
| 그룹 키 병합(같은 날+같은 거래처) | 58.8% → 58.6% | ❌ 무효 |
| 배정 최소 점수 임계 (2~5) | 58.8% → 56.2~45.9% | ❌ 커버리지만 깎임 |

- **간판·시트컷은 파일명에 규격이 1% 뿐**이다(BoundingBox 는 100% 읽히지만 ×1 실척 가정 필요).
  게다가 채널간판 주문은 정답지에 규격이 안 붙어 있어 대응할 상대가 없다 — 노이즈만 늘었다
  (정답지에 없음 7.3% → 9.5%). `메인2~4` 는 아예 주문 축이 아니다(빈 폴더·참고자료·견적 잡동사니).
- 거래처 일치율은 전량일치분 60.5% · 부분일치분 66.3% 로 **차이가 없다**
  → 거래처 불일치는 오배정 신호가 아니라 표기 문제다. **거래처로 게이팅하지 말 것.**

## ★ 지표를 다시 봐야 한다 — 링키지 정확도 ≠ 초안 생성 능력 (3차)

용준님 확인: **지금은 이카운트에 주문서를 먼저 쓰고**, 그 접수일 폴더에 파일을 순서대로 적재한다.
즉 파일은 주문의 **하류**다. 그런데 MES 전환 후에는 이카운트 주문이 **없다** — 파일이 곧 주문이다.
「이 파일 그룹이 이카운트 몇 번 전표인가」(레코드 링키지)는 **전환 후 존재하지 않는 문제**다.

그 증거 — 매칭 실패 그룹도 정보는 똑같이 갖고 있다:

| | 거래처 | 전 파일 규격 | 수량 |
|---|---|---|---|
| 매칭 **성공** 1,465그룹 | 90.2% | 98.4% | 90.7% |
| 매칭 **실패** 329그룹 | **92.4%** | **97.9%** | **92.7%** |

실패 샘플: `04-(매쉬베너)신성에프앤씨-갓지동노은점(62x182-1장)사방큰펀칭-오늘 오후4시 사무실.eps`
— 거래처·건명·규격·수량·후가공·납기·배송이 전부 있다. 못 찾은 건 전표번호뿐이다.

그리고 링키지는 **포화**했다. 날짜창 0/1/2/7일·비대칭 [-4,+1]·[-7,+1]·[-14,+2]·임계값 0~5·
그룹병합·축확대 — 전부 **전량 일치율 76~77%** 붙박이. 튜닝으로 안 오른다.
→ 이카운트는 **표본 검증용**으로만 쓰고, 전건 대조를 목표로 삼지 말 것.

### 날짜 폴더 = 접수일 (완전히는 아니다)

폴더 날짜와 정답지 주문일자가 같은 비율은 **72~83%**. 어긋날 땐 주문일자가 **앞선다**
(−1일 9.9% · −2~−4일 9.3% / +쪽 5.7%) — 접수는 어제, 파일은 오늘 적재되는 경우다.
날짜창을 0일로 조이면 유효 커버리지 44.0%로 떨어진다. **하드 제약으로 쓰면 안 된다.**

### 완료 폴더 — 매칭용이 아니라 완료 표시용

출력이 끝나면 사람이 파일을 옮긴다. 축마다 방식이 다르다:

| 축 | 완료 폴더 | 배송 폴더 | 미이동 |
|---|---|---|---|
| 수성 | **60.5%** (출력실 803·현수막실 425·현수막 226) | 21.6% | 17.9% |
| UV솔벤 | 0% | **94.0%** (택배·화물·방문직배·간판팀) | 6.0% |
| 전사 | 0% | 0% | **100%** (안 옮긴다) |

UV솔벤은 완료 폴더가 아니라 **배송수단 폴더**로 옮긴다 — 기능은 같다(루트=미완료, 이동=완료).

## 병행 운영 안전장치 (2026-08-12) — 3건 구현

이카운트를 병행하기로 하면서 나온 위험 3가지에 대한 대응이다.

### ① 스캐너가 바뀐 파일을 알아챈다 (`zscan-intake.cjs`)

**고친 구멍**: 멱등 키(`source_folder`)만 보고 「전에 올린 파일」을 무조건 건너뛰었다.
규격을 고쳐 다시 저장해도 MES 는 옛 값 그대로 — **조용히 틀리는** 종류의 버그였다.

- 라우트가 중복 시 **기존 값을 함께 돌려주게** 바꿨다(`workbench.ts`)
- 스캐너가 **의미값**(가로·세로·수량·거래처·품목)을 비교해 바뀐 것만 다시 올린다

## ★방향 전환 (2026-08-12) — 주문서는 파일이 아니라 **이카운트**에서 만든다
