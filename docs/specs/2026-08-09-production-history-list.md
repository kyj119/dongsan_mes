## 0. 조사로 드러난 사실 (설계 전제를 바꾼 것)

| # | 사실 | 근거 | 함의 |
|---|---|---|---|
| 1 | **`cards` 0건 · `production_logs` 0건** (prod) | remote 집계 | 카드/작업일지 기준 실적목록은 **빈 화면**이다 |
| 2 | **`print_events` 2,651건** — 그리고 **2026-08 에도 352건**이 쌓이고 있다 | `GROUP BY substr(...,1,7)` → 06:858 · 07:1,441 · 08:352 | 주문·출고는 7월에 멈췄는데 **장비 로그만 살아 있다.** 유일한 실시간 생산 데이터 |
| 3 | 전량 `event_kind='PRINT'`, `print_status` = OK 2,442 · **CANCEL 203 · ERROR 6** | remote `GROUP BY` | 취소·오류가 섞여 있다. 실적으로 세면 부풀려진다 |
| 4 | 전량 `print_completed_at` 있음 | 같은 쿼리 (완료=n) | 시간축은 신뢰 가능 |
| 5 | **`card_id` 연결이 단 1건** | `SUM(card_id IS NOT NULL)` = 1 | 주문·거래처·금액을 **붙일 수 없다** |
| 6 | `actual_printed=1`(실출력 확인) **0건** | remote 집계 | 확인 플래그는 현재 미사용 — 실적 판정 근거로 못 쓴다 |
| 7 | 장비 `equipment` 26대 중 월 **17~21대**가 실제 이벤트 발생 | `COUNT(DISTINCT equipment_id)` | 장비축 집계가 의미 있다 |

**출고 이력에서 겪은 것과 같은 구조다** — "당연히 여기 있겠지" 싶은 테이블(`cards`)이 비어 있고, 실제 데이터는 다른 곳(`print_events`)에 있다.

## 1. 이 목록이 답해야 하는 질문

지금 `/production` 은 "오늘 무슨 일이 벌어지고 있나"만 보여준다. 되짚을 수단이 없다.

1. 지난주 **어느 장비가 얼마나** 돌았나
2. **취소·오류가 어디서** 나는가 (장비별·기간별)
3. 특정 **파일/주문번호**가 언제 출력됐나 (재출력 여부 확인)
4. 출력 **면적(㎡)** 기준 실적 — 건수만으로는 실적이 안 잡힌다

## 2. 핵심 설계 판단

### 2-1. 정본 = `print_events`, grain = 출력 이벤트 1건

카드·작업일지가 비어 있으므로 선택의 여지가 없다. 그리고 이 선택은 **지금 데이터가 쌓이는 쪽**이라 화면이 즉시 쓸모 있다.

한계를 명시한다: **거래처·금액을 붙일 수 없다**(`card_id` 연결 1건). 이 목록은 **장비 실적**이지 매출 실적이 아니다. 화면 제목·칩에 그 사실을 적는다.

> 파일명 매칭 파이프라인(`resolveCard`)이 살아나 `card_id` 가 채워지면 주문번호·거래처 열을 덧붙인다(§6 후속).

### 2-2. ★ 취소·오류를 실적에서 빼되 숨기지 않는다

`CANCEL` 203 · `ERROR` 6 이 섞여 있다. 그냥 세면 실적이 **7.9% 부풀려진다.**

출고 이력의 회계 전표 제외와 **같은 방식**으로 처리한다:

| 요소 | 처리 |
|---|---|
| 기본 조회 | `print_status='OK'` 만 (실적) |
| 상태 필터 | 전체 / 정상 / 취소 / 오류 4택 |
| 칩 | 기본 조회 시 **"취소·오류 N건 제외"** 를 회색 칩으로 상시 표기 |
| 합계 바 | 정상분만 집계. 취소·오류는 **별도 항목**(`취소 N · 오류 N`)으로 병기, 합계에서 빼지 않는다 |

반품에서 세운 원칙과 같다 — gross 와 net 은 다른 질문이고, 한 숫자로 합치면 어느 쪽도 못 본다.

### 2-3. 실적 지표 = 건수 + 면적(㎡) + 소요시간

건수만으로는 실적이 안 잡힌다(A4 한 장과 10m 현수막이 같은 1건).

| 지표 | 산식 | 비고 |
|---|---|---|
| 건수 | `COUNT(*)` | |
| 출력 면적 | `SUM(output_width * output_height * COALESCE(copy_total,1)) / 1e6` ㎡ | mm 기준이면 1e6 으로 나눈다. **단위 확인 필요**(§7) |
| 소요시간 | `SUM(print_duration_sec)` | ⚠️ `duration` 의미가 파서별로 다르다 — memory `reference-logwatcher-duration-semantics`. 합산 전 확인 필요 |
| 장비 수 | `COUNT(DISTINCT equipment_id)` | |

⚠️ `copy_total`·`tile_count` 가 있으므로 **면적을 원본 1장 기준으로 세면 안 된다.** 모아찍기·타일 출력이 실제 소모 면적이다.

### 2-4. 배치 — `/production` 에 「실적」 탭

흡수-탭 패턴. 사이드바·권한 등록 불요. 오늘 현황을 보다 과거를 되짚을 때 페이지 이동이 없다.

## 5. 검증 계획

- 상태 기본값(정상만)에서 취소·오류가 빠지고 칩에 제외 건수가 뜨는지
- 면적 합계가 `copy_total` 을 반영하는지 (모아찍기 1건 vs 단건 비교)
- 8월분(352건)이 조회되는지 — 살아 있는 데이터로 확인
- 정렬 tie-break (`print_completed_at DESC, id DESC`) — `sort-audit`
- 탭 왕복 시 도구모음 중복 마운트 없음
- prod smoke 110/110

## 7. 실측 결과 (구현 전 확인 항목 — 전부 해소)

| # | 항목 | 실측 | 결론 |
|---|---|---|---|
| 1 | `output_width/height` 단위 | 40mm ~ 27,840mm(27.8m). 파일명 `60-45-40장` 인 행이 `629.9 × 500.4` | **mm 확정.** 단 **TEXT 컬럼**이라 `CAST(... AS REAL)` 필수 — 안 하면 문자열 비교로 MIN/MAX 가 뒤집힌다(실제로 `minw='1000' > maxw='990.141'` 로 나왔다) |
| 2 | `print_duration_sec` | 1초 ~ 14,293초. **100장 작업이 45초**인 행 존재, NULL 211건 | **합계에서 제외.** 열로만 원본을 보여준다. memory `reference-logwatcher-duration-semantics` 가 경고한 그대로 |
| 3 | `copy_total` vs `tile_count` | 타일 행은 **타일마다 폭이 다르다**(2473mm / 1807mm, 같은 파일) | 행이 이미 타일 단위로 분리돼 있다 → **`copy_total` 만 곱한다.** `tile_count` 를 곱하면 중복 |

면적 산식 = `CAST(w AS REAL) * CAST(h AS REAL) * COALESCE(copy_total,1) / 1e6` ㎡. prod 전체 OK 이벤트 = **61,818㎡**.
