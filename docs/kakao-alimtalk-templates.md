# 카카오 알림톡 템플릿 문안 (동산기획)

> 연동 페이지: **`/messages` (메시지 관리)** · 발송 엔진: 바로빌 `KakaoTalk.asmx` (`SendATKakaotalk`)
> 이 문서의 템플릿을 **바로빌 사이트에 등록 → 카카오 검수 통과** 후 MES가 자동으로 조회·발송합니다.
> 최종 갱신: 2026-06-03 (코드 대조 점검 완료본)

---

## 0. ⚠️ 먼저 알아둘 2가지 (코드 점검 결과)

1. **알림톡 버튼은 현재 전송되지 않습니다.**
   `src/services/barobillSms.ts` 의 `sendATSSingle`/`sendATSBulk` 가 SOAP `<KakaotalkMessage>` 에 버튼 필드를 넣지 않습니다. `/api/kakao/send`·`/api/messages/send`·`send-shipment-bulk` 어디서 `btns` 를 넘겨도 카카오엔 나가지 않습니다.
   → **모든 링크(포털·배송조회)는 본문 텍스트로 전달**합니다. (버튼 기능은 별도 코드 개선 과제, §6 참고)

2. **출고는 배송수단별로 템플릿을 분리 등록**합니다.
   배송 문구(`■ 배송: 대신화물` 등)가 수단마다 달라 카카오 "템플릿 1개 = 본문 1개" 규칙상 단일 템플릿으로는 안 됩니다. `delivery_type` 이 `FREIGHT`/`DELIVERY` 영문코드라 변수 통합도 불가 → **4종 분리**.

## 1. 핵심 원리 — "등록 템플릿 = 발송 본문"

카카오 알림톡은 **등록·승인된 템플릿의 고정 텍스트와 발송 본문이 글자 단위로 일치**해야 발송됩니다.
`#{변수}` 위치만 임의 값으로 치환 가능하고, 고정 문구가 1글자라도 다르면 **발송 거부**(또는 대체문자 전환)됩니다.

아래 문안은 **MES 코드가 실제로 만들어 보내는 본문**과 1:1로 맞췄습니다. 바로빌 등록 시 **본문·변수명·`템플릿 코드(TemplateName)`를 그대로** 사용하세요.

### 발송 경로 (코드 기준)

| 경로 | 화면 | 라우트 | template_code | 변수 치환 위치 |
|------|------|--------|---------------|----------------|
| 직접 호출 | 출고 `/shipments` | `POST /api/kakao/send-shipment-bulk` | shipments.js `autoCodeMap` 자동선택 | **서버** `resolveMsg` (`src/routes/kakao.ts`) |
| 직접 호출 | 미수금 `/ledger` | `POST /api/kakao/send` | ledger.js 자동선택 `ledger_notice` | **클라이언트가 완성본 전송**(변수 없음) |
| 공통 모달 | 주문접수 `/orders` 등 | `POST /api/messages/send` | orders.js `autoTemplate` | **클라이언트** `templateVars` 치환 (`onMsgTemplateChange`) |

### 서버 치환 변수 (출고 전용, `resolveMsg`)
`#{고객명}` `#{품목}` `#{송장번호}` `#{터미널}` `#{배송방법}` `#{날짜}` — 정규식 치환 동작 확인 완료.

### 3-5. 주문 접수 확인 — `[order_received]`

- 연동: `/orders` 목록 행 **✈️** → `sendOrderNotice()` → 공통 모달 → `POST /api/messages/send`. 등록 템플릿 본문을 불러와 `templateVars` 로 치환.

```
#{고객명}님, 동산기획입니다.

주문이 정상 접수되었습니다.

■ 주문번호: #{주문번호}
■ 품목: #{품목}
■ 접수일: #{날짜}

진행 상황은 추후 안내드리겠습니다.
감사합니다.

문의: 042-523-1982
```

| 변수 | 의미 | 데이터 소스 (`orders.js` `templateVars`) |
|------|------|------------------------------------------|
| `#{고객명}` | 거래처명 | `clientName` |
| `#{주문번호}` | 주문번호 | `orderNumber` |
| `#{품목}` | **메인품목[규격][내용] 외 n건** | `formatOrderItemSummary(order)` |
| `#{날짜}` | 접수일 | `today` |

- 품목 형식 예: `현수막[3000×1000][실사출력] 외 2건` (order_items의 `item_name`/`width×height`/`content`/건수)
- 검수용 `#{품목}` 예시값: `현수막[3000×1000][실사출력] 외 2건`
- 버튼 없음

> ✅ **코드 적용 완료**: `orders.js` `autoTemplate` → `order_received`, `templateVars` = `{고객명, 주문번호, 품목, 날짜}`, `core.ts` 주문목록 쿼리에 `main_item_content` 추가.
> ⚠️ 기존 `026040001087` 은 더 이상 사용 안 함 → 바로빌에 **`order_received` 새로 등록** 필요(위 본문·변수 4개로).

### 3-6. 거래내역 / 미수금 안내 — `[ledger_notice]`

- 연동: `/ledger` 발송 모달 → `POST /api/kakao/send`. 발송 시 1회용 포털 링크가 **본문 끝에 자동 추가**됨.
- 변수 치환 없이 **클라이언트가 완성본을 전송** → 등록 템플릿의 고정부가 아래와 정확히 일치해야 함.

```
#{고객명}님, 동산기획입니다.

거래 내역을 안내드립니다.

■ 미수금: #{미수금}
■ 기준일: #{기준일}

상세 내역은 아래 링크에서 확인하세요.

문의: 042-523-1982

▶ 거래 내역 확인: #{링크}
```
- 변수: `#{고객명}`=거래처명 · `#{미수금}`=미수 잔액(예 `1,250,000원`) · `#{기준일}`=조회일 · `#{링크}`=1회용 포털 URL
- 버튼 없음 (포털 링크는 위와 같이 **본문 마지막 줄**로 전달).

> ledger.js 본문(`■ 미수금: …` / `상세 내역은 아래 링크에서 확인하세요.`) + 발송 시 `▶ 거래 내역 확인: #{링크}` 추가 구조와 1:1 일치.

**발송 모달 동작** (`/ledger` 행 ✈️ → `openLedgerSendModal`): 기본 채널 **SMS**. 채널 토글로 카카오톡 선택 시 템플릿 select(자동 `ledger_notice`) 표시. **본문 textarea는 채널과 무관하게 항상 표시·편집 가능**.

**⚠️ 알림톡 사용 시 주의 (점검 결과)**
1. **본문 편집 위험**: 본문을 수정하면 등록 템플릿과 불일치 → 알림톡 발송 거부(→SMS 대체). 알림톡으로 보낼 땐 본문을 **그대로 두어야** 함. (개선안: 알림톡 채널 선택 시 본문 readonly — §6)
2. **가변 포털 링크**: `#{링크}`가 7일 1회용 토큰 URL. 카카오 검수에서 **가변 URL 반려** 가능 → 도메인 고정 여부 확인 필요.
3. **토큰 실패 시**: 포털 토큰 생성 실패하면 링크 줄이 누락돼 불일치 가능(드묾).

> 💡 **권장**: 미수금/거래 안내는 금액·링크가 매번 달라 **SMS/LMS가 더 유연**(모달 기본값도 SMS). 알림톡 `ledger_notice` 등록은 "정형 안내를 저렴·고도달로 보내고 싶을 때"의 선택지로 두고, 등록 시 위 3가지를 반영.

## 4. 바로빌 등록 절차

1. 바로빌 로그인 → **알림톡 → 발신프로필(채널) 등록** (`@동산기획`). 채널 검색용 ID를 MES `설정 → kakao_channel_id` 에 입력.
2. **알림톡 → 템플릿 등록** → §3 본문을 ```` ``` ```` 코드블록째 복사·붙여넣기. **TemplateName 은 코드명(`shipment_freight` 등) 그대로**. 변수 `#{}` 유지.
   - 메시지 유형: **기본형** · 강조유형: **선택안함** · 버튼: **없음** (전 템플릿 공통)
   - 검수용 변수 예시값 입력: `#{고객명}`→홍길동, `#{품목}`→현수막 외 2건, `#{송장번호}`→123456789012, `#{날짜}`→2026-06-03, `#{미수금}`→1,250,000원, `#{기준일}`→2026-06-03, `#{링크}`→https://example.com/portal/abc
3. 카카오 검수 신청 → 승인(영업일 1~2일).
4. MES `/messages → 템플릿 관리 → 카카오톡 → 새로고침` → 승인 템플릿이 보이면 연동 완료.
5. `/messages` 상단에서 발신번호(`kakao_sender_num`) · 활성화(`kakao_enabled=1`) 확인.

### 우선 등록 권장 순서
출고 4종(`shipment_freight`/`shipment_hanjin`/`shipment_parcel`/`pickup_ready`) → `ledger_notice` → 주문접수.

## 6. 후속 과제 — 버튼 전송 구현 (참고)

현재 `barobillSms.ts` `sendATSSingle`/`sendATSBulk` 의 SOAP body에 버튼 노드가 없습니다. 바로빌 `SendATKakaotalk` 의 버튼 복합타입(WSDL) 스키마를 확인해 `<Button>`(또는 해당 노드)을 추가하면, `btns`(`{n,t,u1,u2}`)를 실제 알림톡 버튼으로 보낼 수 있습니다. 구현 시:
- 한진 출고: `shipment_hanjin` 에 `#{송장번호}` + 배송조회 버튼(WL, `https://trace.hanjin.co.kr/...waybillNo=#{송장번호}`) 복원.
- 미수금: `ledger_notice` 의 본문 링크를 "거래 내역 확인" 버튼으로 전환.
- ⚠️ 단, 카카오 변수형 URL 버튼 지원 여부를 바로빌 측에 먼저 확인.
